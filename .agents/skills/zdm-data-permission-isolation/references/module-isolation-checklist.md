# 模块隔离验收清单

只填写当前模块适用项；不适用项写明原因。产品语义以 Notion 有效文档《多用户端组织与业务数据隔离原则》为准。

## 设计

- [ ] 数据已分类为平台公共、组织私有或跨组织协作。
- [ ] 已明确平台、租户、门店或其他组织作用域。
- [ ] 已列出各用户端读取、创建、修改、删除和代处理职责。
- [ ] 公共数据例外或跨组织共享具有有效产品依据。
- [ ] 功能权限与数据权限分别定义。

## 数据库

- [ ] 组织归属能够持久化且无歧义。
- [ ] 门店数据能够确认所属租户和门店。
- [ ] 唯一索引、外键和检查约束限定正确作用域。
- [ ] 创建人或负责人没有被误作组织字段。
- [ ] 已列出应删除的旧表、字段、编码、兼容逻辑和测试数据。

## 服务端

- [ ] 当前作用域来自统一身份上下文。
- [ ] 列表、详情、统计、导出和分页总数使用同一作用域。
- [ ] 新增由服务端写入组织归属。
- [ ] 修改、状态变更、删除和批量操作重新校验目标归属。
- [ ] 关联对象不能跨越允许的组织范围。
- [ ] 功能权限、数据权限、组织归属和业务状态均在服务端校验。
- [ ] 拒绝结果不泄露其他组织的数据是否存在。

## 前端

- [ ] 菜单、路由、Tab 和操作入口使用统一权限结果。
- [ ] 页面展示当前身份和组织。
- [ ] 客户端不能通过组织参数覆盖当前安全作用域。
- [ ] 公共只读、私有可编辑或代处理状态与产品规则一致。

## 自动化验证

- [ ] 当前组织正常读取和操作。
- [ ] 其他用户端不可越权。
- [ ] 其他租户不可越权。
- [ ] 同租户其他门店不可越权。
- [ ] 详情、修改、删除、导出和批量接口覆盖直接请求。
- [ ] 伪造租户、门店或组织参数无效。
- [ ] 身份或组织切换后旧数据和权限立即失效。
- [ ] 公共基础数据按规则可读且下游不可越权修改。
- [ ] 角色、员工和其他关联对象不能跨组织绑定。
- [ ] 历史错误绑定不能继续产生权限。

## 运行态验收

- [ ] 使用运营平台代表身份验证。
- [ ] 使用每个适用用户端的代表身份验证。
- [ ] 至少使用两个租户或两个门店完成交叉验证。
- [ ] 页面表现与接口返回一致。
- [ ] 记录测试账号、当前身份、目标组织和验证结果。
