# 装点猫数据权限隔离

## 权威规则

1. 使用 `zdm-product-knowledge` 读取 Notion 有效文档《多用户端组织与业务数据隔离原则》；账号、身份、角色和功能权限同时读取其上位文档《统一账号与权限体系原则》。
2. 只把 Notion 有效文档作为产品语义来源。本 Skill 只规定执行流程，不复制业务规则。
3. 用户当前明确要求与文档冲突时，执行用户要求并明确列出需要回写的产品决策；未经授权不修改 Notion。

## 工作流

### 1. 确认数据归属

- 将模块数据明确分类为平台公共基础数据、组织私有数据或跨组织协作数据。
- 明确当前合法作用域是平台、租户、门店还是其他组织；归属不清时先停止实现并确认。
- 对跨组织协作数据列出参与组织、各方可见字段、允许操作、状态条件和审计要求。
- 不从现有前端筛选、角色名称、创建人字段或历史数据反推产品归属。

### 2. 审查持久化模型

- 确认表结构能无歧义地持久化组织归属，并为唯一性、外键和检查约束限定正确作用域。
- 创建人、负责人、经办人等人员字段不得替代组织字段。
- 组织归属由服务端根据当前身份写入；不得接受客户端覆盖安全作用域。
- 新模型确定后，列出应删除的旧表、字段、权限编码、兼容逻辑和测试夹具；共享数据库物理清理继续遵循项目数据库安全流程。

### 3. 实现服务端强制隔离

- 从统一当前身份和组织作用域入口获取范围，不在各接口自行猜测。
- 对列表、详情、统计、导出、批量操作使用一致的作用域条件。
- 新增时写入当前组织；修改、状态变更和删除前重新校验目标归属。
- 校验所有关联对象属于允许的组织范围，尤其是角色、员工、客户、订单和供应关系。
- 同时校验功能权限、数据权限、组织归属和业务状态；前端隐藏不能替代服务端校验。
- 拒绝跨组织请求时不泄露目标记录是否存在。
- 涉及组织归档、恢复或彻底删除时，先按有效 PRD 确认组织总闸门、子级组织联动归档来源与精准恢复、其他子级状态保留、会话失效、删除预检、跨组织阻断和账号保留边界；删除范围必须在事务内重新计算，不信任前端预检。

### 4. 实现前端消费

- 菜单、路由、Tab 和按钮使用统一有效权限结果。
- 展示当前身份及组织，避免使用历史缓存或固定文案。
- 不提供能够覆盖当前安全作用域的租户、门店或组织参数。
- 公共数据和私有数据在交互上有差异时，使用产品规则定义的只读、可编辑或代处理状态。

### 5. 验证闭环

实施和审查时完整读取 [模块隔离验收清单](references/module-isolation-checklist.md)，按当前模块标记适用项并提供证据。

至少覆盖：

- 当前组织正常访问。
- 跨用户端、跨租户、跨门店读取被隔离。
- 详情、修改、删除和批量接口不能通过构造请求越权。
- 伪造组织参数无效。
- 公共基础数据只按规则共享。
- 身份或组织切换后不沿用旧权限和数据。
- 角色、员工及其他关联对象不能跨组织绑定。
- 历史错误绑定和旧权限编码不能继续生效。
- 组织归档后所有适用身份和既有会话失效；租户恢复仅恢复带联动归档来源的门店，不覆盖手动归档门店及其他子级原状态。
- 组织彻底删除覆盖事务回滚、共享账号保留、独占账号释放凭证及跨组织引用阻断。

## 交付要求

- 报告数据分类、作用域、数据库归属表达和各用户端职责。
- 报告后端强制点、前端消费点、公共数据例外及跨组织协作边界。
- 报告验收身份、越权用例、运行结果、未运行项和剩余风险。
- 未完成服务端隔离或越权测试时，不把模块描述为已完成数据隔离。

## 守门规则

- 不使用前端过滤、菜单隐藏或路由守卫作为数据安全证明。
- 不以超级管理员、运营平台或 `all` 权限自动推断可读取所有组织业务数据。
- 不建立与 Notion 权威规则平行的项目事实副本。
- 不为来源不明的历史记录猜测租户或门店归属。
- 不因一个入口同时服务多个用户端，就共享其组织私有数据。
