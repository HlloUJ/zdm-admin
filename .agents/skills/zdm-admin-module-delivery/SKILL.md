# 装点猫后台模块闭环交付

## 开始

1. 读取项目规则，并按 `zdm-product-knowledge` 获取最相关的有效产品原则或 PRD；用户当前明确要求优先。
2. 涉及组织业务数据读取、写入、共享或跨端协作时，同时使用 `zdm-data-permission-isolation`；涉及账号、身份、角色或权限模型调整时，同时使用 `account-permission-rules`。
3. 涉及页面结构或新增页面时，同时使用 `zdm-admin-ui-conventions`；涉及全量功能资源目录登记或调整时，同时使用 `zdm-function-catalog-registration`。
4. 涉及代码修改时，同时使用 `efficient-code-delivery`，按项目 `AGENTS.md` 的风险等级验证。
5. 开始设计和交付前读取 [模块交付清单](references/module-delivery-checklist.md)，只填写与当前模块有关的部分。
6. 同一模块任务后续对话在业务边界、规则和代码基线未变化时复用已读取原则、PRD、UI 约定和交付清单；只补读发生变化或当前阶段新增的部分。

## 工作流

### 1. 确定业务模块边界

- 以业务实体和完整业务任务划分模块，不以运营平台、门店端或供应商端划分模块。
- 明确目标、非目标、上下游依赖、数据归属、状态流转和异常边界。
- 使用 `zdm-data-permission-isolation` 将数据分类为平台公共、组织私有或跨组织协作，并明确合法组织作用域。
- 列出运营平台、门店端、供应商端等适用业务端及各自职责；不适用的业务端明确标记为不适用。
- 保留并核对当前实现、有效产品文档和用户已有改动，不从终端权限树反推业务设计。

### 2. 设计跨端业务切片

- 同一业务实体、字段和主流程基本一致时优先复用页面，通过 Tab、操作权限和数据范围表达差异。
- 业务实体、字段含义、状态流转或主要任务明显不同时拆分 Tab、页面或菜单。
- 先完成业务路径、页面结构、字段、状态、操作和异常设计，再确定权限资源；不要为填充权限目录创造页面或操作。

### 3. 显式登记功能资源

- 全量功能目录必须忠实描述已经实现并验证的真实模块，不作为智能体补全功能的设计稿。
- 使用 `zdm-function-catalog-registration` 完成真实页面盘点、一比一登记、权限编码和目录专项验证；不得在本 Skill 中维护另一套登记细则。
- 页面实现完整候选操作，再由终端功能范围、角色权限和数据范围决定实际可用能力。

### 4. 实现业务与权限控制

- 复用当前项目的数据模型、接口、路由、页面基座和基础组件。
- 前端菜单、路由、页面 Tab 和按钮使用统一权限结果；无权限时不展示或拒绝进入。
- 服务端对对应接口同步校验业务身份、功能权限、数据范围和业务状态，不能只依赖前端隐藏。
- 区分权限与状态：没有权限时拒绝访问；拥有权限但当前业务状态不允许时按业务规则禁用或报错。

### 5. 发布功能资源

- 模块实现并通过相应验证后，将真实资源加入全量功能资源目录，并标记为可分配。
- 终端功能分配从统一资源目录读取候选项，不为每个业务模块编写独立渲染和数据副本。
- 若当前实现尚未具备统一资源存储，更新当前权威目录并保持编码、层级和迁移路径一致；不要模拟自动发现。
- 新资源可以自动进入候选目录，但不得自动启用给任何业务端，也不得自动授予既有角色。

### 6. 配置终端、角色与数据范围

- 终端功能分配决定门店端、供应商端等业务端的功能上限。
- 角色只能从所属业务端已允许的功能中选择权限。
- 数据权限单独限定本人、本组织、指定范围或全部数据，不与功能权限混用。
- 普通身份的有效功能权限取当前身份适用范围、终端功能范围和角色权限的交集。

### 7. 验证模块闭环

- 验证全功能开发测试身份能够覆盖模块全部路径和操作。
- 分别使用各适用业务端和代表性角色验证菜单、页面、Tab、按钮及数据范围。
- 验证无权限用户通过直接路由、请求构造或接口调用仍被拒绝。
- 验证业务状态限制、跨组织隔离、权限变更后的刷新和受影响模块回归。
- 只将真实存在并通过验证的权限资源标记为可分配。

### 8. 完成交付

- 报告模块业务边界、适用业务端、共享与拆分结果。
- 报告实际修改目录、功能资源层级、终端策略、角色权限和数据范围。
- 报告验证结果、未运行项、待确认事项和是否跨项目。
- 未完成资源登记、终端与角色边界或必要权限验证时，不将模块表述为完整闭环。

## 守门规则

- 业务设计优先于权限目录，权限目录必须忠实描述真实模块。
- 全量功能目录是实际权限资源的镜像，不是智能体补全功能的设计稿；没有可核验事实就不登记。
- 发现当前代码、有效文档和用户描述不一致时，列出差异并请求用户确认，不以任何一方为由自行创造折中权限。
- 功能资源目录、终端功能分配和角色权限使用同一套资源编码，不维护互不关联的副本。
- 新增模块应新增标准功能资源，不应要求终端功能分配页面增加模块专属逻辑。
- 普通字段增补或纯缺陷修复若未改变模块边界、权限资源或业务流程，沿用现有规则，不强制执行完整模块闭环。
