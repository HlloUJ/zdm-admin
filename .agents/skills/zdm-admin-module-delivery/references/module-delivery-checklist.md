登记全量功能目录前必须逐项满足：

- [ ] 每个菜单、页面和 Tab 都能在当前真实路由或界面中定位，不以规划稿或相邻模块推断。
- [ ] 已逐项盘点真实页面的 Tab 和页面业务按钮，目录与盘点结果的层级、名称、顺序和数量一比一一致。
- [ ] 没有合并、概括、改名、遗漏、拆分或自行新增任何 Tab、页面业务按钮；边界不明确的项目已经询问用户。
- [ ] 无 Tab 页面已由统一目录生成页面级 `.view`，有 Tab 页面已为每个 Tab 生成 `.view`，没有由模块手工重复维护。
- [ ] 每个操作权限都有真实操作入口、现有稳定权限编码和前后端实际校验。
- [ ] 没有为了 CRUD 完整、目录对称或测试便利补充任何功能或权限。
- [ ] 树形展开/收起及弹窗保存、确认、取消、我知道了等纯交互控件未登记为独立权限，除非用户明确要求。
- [ ] 每个非查看操作均依赖同一页面或 Tab 的 `.view`，取消查看时不会遗留可执行操作。
- [ ] 没有把普通按钮、业务状态按钮或说明性 Tab 虚构成可分配权限。
- [ ] 自动化测试已断言目录中真实 Tab、页面业务按钮的名称、顺序和数量。
- [ ] 任一证据缺失的资源均已标记“待确认/未登记”，没有写入全量功能目录。
