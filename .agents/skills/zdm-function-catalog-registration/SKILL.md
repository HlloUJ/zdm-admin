# 装点猫全量功能目录登记

## 开始

1. 读取项目规则、当前权威功能目录及其终端功能分配和角色权限消费者。
2. 从当前真实路由、页面源码和必要的运行界面逐项盘点目标模块；产品边界不明确时使用 `zdm-product-knowledge`，用户当前明确要求优先。
3. 只处理用户指定模块，不顺带整理或补齐其他模块。

## 一比一登记

- 按真实层级登记：**一级菜单 → 二级菜单或一级直达 → 页面 → 页面 Tab → 操作权限**。
- 目录必须与已确认的真实页面元素一比一，保持相同层级、名称、顺序、数量和动态状态文案。
- 禁止智能体自行发挥：不得合并多个 Tab 或按钮，不得概括、改名、遗漏、拆分、自行新增，也不得为 CRUD 完整、目录对称或测试便利补齐资源。
- 查询、重置是获得查看权限后的页面基础交互，不登记为全量功能目录中的独立操作权限。展开/收起、弹窗确认等其他控件是否登记，必须以当前明确范围为准；范围不清时停止并询问用户，不自行归类。
- 只能登记当前真实实现中存在且可核验的资源。规划项、占位页面、说明性 Tab 和不存在的按钮不得进入可分配目录。
- 无 Tab 页面使用页面级 `.view`，有 Tab 页面使用各 Tab 的 `.view`；其他操作分别使用稳定且唯一的权限编码。
- 用户未明确要求新增权限模型时，不擅自扩大为页面或后端权限改造；但必须如实报告目录编码是否已有前后端校验，不能把仅完成登记表述为权限闭环。

## 同步与验证

- 更新统一权威目录，不在终端功能分配、角色管理或其他消费者中维护功能数据副本。
- 检查目录行结构、权限依赖和旧编码归一化是否会合并、过滤或改写本次资源。
- 自动化测试必须精确断言目标模块的菜单、页面、Tab、操作名称、顺序、数量和权限编码，并确认操作权限中没有查询、重置。
- 验证终端功能分配与角色权限界面读取同一目录，并实际显示本次登记结果。
- 发现代码、有效产品规则和用户描述冲突时，列出差异并请求确认，不创建折中目录。

## 交付

- 报告实际登记层级、明确排除项、权限编码和共同消费者。
- 区分“已登记目录”“已接入前端控制”“已完成后端校验”，只陈述实际完成状态。
- 报告验证结果、未运行项、当前分支、提交和推送状态。
