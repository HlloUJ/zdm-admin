# 管理后台开发效率与质量基线

最后更新：2026-09-23

本文是 `/Users/uj/Documents/Codex/装点猫/管理后台` 当前有效的开发效率、预览环境、数据库保护、验证和 Git 交付基线。

## 目标

- 按微改、页面逻辑、权限、后端与交付分别计时；不把历史“四分钟”作为统一预算或停止条件。
- 按真实风险保留权限、API、后端、数据库和运行态证据，不以时间目标替代质量门禁。
- 减少重复读取、长日志、Notion/GitHub 查询、全量验证和逐轮提交推送。

## 批次连续开发

同一仓库、准备一起交付的串行模块默认属于一个批次，共用独立 `codex/<batch>` 分支、Worktree 和 `5175`。模块独立验收不要求先交付主线；模块之间直接使用累计的本地代码。业务与基建分批，明确不同发布时间或需要并行隔离时另行安排。

1. 开始时一次核对范围、规则和 Git；先读批次登记，只有没有有效批次时才从最新 `origin/main` 创建目录。新对话接续同一批次前确认旧对话已停止写入，登记不充当会话锁。
2. 逐模块记录目标与实际依赖。模块或可独立回滚功能完成后运行必要验证，精确暂存并保存独立本地提交；后续反馈继续同目录，不按每条反馈提交、不推送、不重复创建环境。
3. “这个模块可以了，继续下一个”表示模块验收；“任务完成”或明确结束当前批次才触发整批交付。唯一已登记批次的清单持续可查，不重复请求逐模块授权；“今天”不自动收集其他分支、项目或来源不明改动。
4. 整批交付补齐受影响及跨模块验证，核对所有自有提交都有模块归属。暂停、排除和未完成模块的代码仍在分支时必须先处理，不能仅从清单隐藏后整批合入。
5. 集中推送、运行最终候选 CI、合并主线并完成交接。保留模块提交，优先普通 merge，不默认 squash 或改写已发布历史。仓库策略冲突时报告，不能强制变更策略。
6. 同步并核对远程与本地 `main` SHA 一致，再审计清理本批次 Git 载体并归档登记。`codex/integration-current` 只运行正式汇入的组合，始终不用于业务开发，也不整体合入主线。

尚未登记的旧任务不自动迁移、提交或覆盖；在明确恢复且范围可证明时才登记。现有原任务提交授权继续有效。集成冲突只处理当前交付必要范围，范围外冲突停止并保留现场。

### 批次工具

登记保存在仓库 Git 公共目录 `task-batches/active.json`，同仓库各 Worktree 可见；关闭后索引保留在 `task-batches/archive/`，不随任务目录清理。工具不自动提交、推送、合并、回滚或删除代码，不替代真实测试、CI 和运行交接证据。

操作命令见 [本地启动与验收指南](dev-setup.md#批次开发与恢复)。`checkpoint` 只登记已经存在的本地 Git 提交及实际验证依据，不是勾选即可放行；归档查询仍需核对交付之后出现的新消费者。

### 局部回滚与共享环境

- 本地提交按模块或可独立回滚功能划分，真正共用的能力独立记录；只维护实际依赖，不提前设计通用基座。
- 回滚计划列出直接和传递依赖，并结合当前代码、API、配置和迁移检查真实消费者。登记是线索，不能证明所有运行依赖已穷尽。
- 撤回功能但允许保留公共能力时，明确保留范围；核心能力也必须移除时先检查兼容实现。必须改变关联模块既有行为时，展示具体影响、替代方案与撤回方式，批准后再实施；不能自动停用其他模块。
- 回滚通过新的撤销或修复提交完成，保留历史并验证被撤功能和依赖链；不会因删除批次分支而失去已经合入主线的模块提交。
- 后端模式按整批累计差异判断，本地 checkpoint 不会让前面模块的后端需求消失。模块间复用进程，真实代码变化仍需重载和健康核验。
- 共享数据库锁按批次持有，迁移保护可能暂停集成后端并延长环境占用。后续高风险操作重新评估备份；代码 checkpoint 不等于数据恢复点，回滚代码不自动回滚数据或恢复整批最初备份。整批交付后仍恢复集成并释放锁。

| Playwright   | `127.0.0.1:5174`      | 自动化页面测试                   |

首次运行 `npm run dev:task:install` 安装用户级 `launchd` 服务；之后 `npm run dev:task` 只把 5175 切换到当前 Worktree。5175 不依赖终端存活并在 macOS 登录后恢复上次任务；没有任务或完成交接时自动代理到 5173。Docker Desktop 未运行时由守护服务后台启动并等待任务依赖就绪，任务后端仍按改动按需启动。纯前端任务使用任务前端和集成后端；后端、API、Flyway 或运行配置任务使用任务前端和任务后端。

## 唯一开发数据库

- 5173、5175、集成后端和任务后端共同使用 `zdm-platform-mysql` 中的 `zdm_admin`。
- 不按任务创建 MySQL，不克隆集成库，不做预览库与集成库的数据复制或回写。
- 用户在 5175 手工验收产生的数据直接持久化到集成库，并被后续任务继续复用。
- 页面 E2E 使用接口 Mock；后端测试使用 Testcontainers。自动化测试数据不进入集成库。
- MySQL 数据卷长期保留，MySQL 和集成后端容器使用 `restart: unless-stopped`；Docker Desktop 启动后自动恢复。

### 数据库保护

- Flyway 文件变化自动进入保护流程；批量删除、清空或破坏性导入等非迁移任务显式使用 `--database-risk`。
- 任务后端启动前检查 Flyway 失败记录和其他共享数据库任务后端；存在其他写入者时停止并报告，不批量停止。随后暂停当前任务与集成后端，创建并校验 gzip 备份。
- 集成数据库可能领先于 `main`；启动器合并集成分支与当前任务的迁移目录供 Flyway 校验，同版本不同文件或同文件内容冲突立即停止，不使用忽略迁移规则。
- 保护期间禁止切换到其他任务；迁移或启动失败时保留备份和现场，不自动恢复。
- 表或字段删除、大批量数据删除、数据库恢复必须先报告影响并取得用户明确确认。
- 数据库结构只通过 Git 中的 Flyway 迁移交付，禁止只执行手工 DDL。
- 集成同步和运行交接统一按[交付启动器选择](dev-setup.md#交付启动器与首次升级)及项目适配执行；已完成的交接只复核实际状态，有缺口时沿同一已选兼容启动器完成。集成包含任务提交且运行环境核验通过后才释放所属数据库锁，备份继续保留。

本方案面向当前单人串行开发。未来两人或多人并行修改数据库结构时，必须重新评估并引入独立数据库或冻结验收方案，不能直接沿用共享写入模型。

## 验证路由

风险分级、本地与 CI 的分工及工具授权统一遵循 [项目规则](../AGENTS.md#验证与工具)，具体入口见 [本地启动与验收指南](dev-setup.md#常用验收命令)。

低风险改动按实际影响执行变更检查，并补足覆盖相关交互所需的单测或 E2E；验证范围和用例数量由覆盖需要决定。影响边界不明、高风险需要完整回归、验证器排障，或 CI 缺失、不可靠、覆盖不明时，按项目规则升级本地完整或专项验证。普通正式交付由可靠 CI 对最终候选承担全部适用门禁；本地通过不能覆盖 CI 实际失败，也不能绕过分支保护。

## 验证证据与执行

`npm run verify:delivery -- --list` 先列受影响计划，`npm run verify:local -- --list` 列完整自动化计划，均不启动 Docker 或服务。`verify:delivery` 包含已提交、未提交、未跟踪和删除文件；缺少主线或分类不明时回到全量。正式交付前仍需核对最新主线，不能把旧基线当成当前候选。

普通任务不再固定执行“完整本地 + 完整 CI”两套门禁。本地先发现当前修改问题，最终 CI 负责完整适用覆盖。执行器只复用同一覆盖范围、命令和有效输入对应的成功证据；`--force` 或 `--no-reuse` 强制重新执行，CI 不使用本地成功缓存。

- `check:changed` 与最终验证使用同一证据协议。完整后端测试证据可供最终门禁使用，后端静态质量检查单独补齐；部分测试不能覆盖完整测试。
- 本地 `.task-verification/` 记录命令、覆盖范围、候选内容、基线、依赖及环境指纹、起止时间、退出码与日志。完整候选在执行前后核对，运行期间任何代码变化均不可报告同一候选通过；单纯提交相同内容不使证据失效。
- 失败、不完整、损坏、执行中代码变化、环境无法证明一致或后端编译/测试产物变化均不得复用。不能仅凭 Git SHA、人工勾选或旧“通过”摘要跳过门禁。
- 已知 Docker Maven 命令仅将后端源码、实际执行链、相关配置、工具及测试镜像纳入后端输入，不因无关文档、前端依赖或其他项目镜像改变而失效。Maven 仓库仍保留全量内容指纹，尚未实现解析后的精确依赖图；不可确定的动态镜像、依赖或环境回退实际执行。浏览器环境不能完整证明时重新执行 E2E。
- Mock 浏览器和隔离 Testcontainers 测试不隐式启动或改配共享真实后端。生产后端、API、迁移和运行配置改动仍要先按启动器准备正确任务环境，再由 `dev:task:check` 核验预览身份；显式完整自动化需要同时检查现场环境时加 `--runtime`。用户可见改动的 5175 预览、数据库保护及正式交接要求不变。
- 独立检查可并行，有依赖或共享可变资源的操作保持顺序。成功日志只输出摘要，失败输出必要尾部并指向完整日志。
- 后端精确测试只适用于已建立消费者映射的内部实现；当前覆盖 `SlabLogChanges` 和消费者可证明的 `FinishedSpecValidator`，并保留 API、数据范围和模块边界回归。权限、公开接口、配置、迁移、依赖及未映射修改均回退完整后端测试。

## CI 与交付等待

### 测试与工具自身的开销

- 使用类级 Testcontainers 的 Spring 测试先通过 `SpringContainerTestSupport` 关闭并驱逐当前上下文，再让扩展停止测试数据库；后台调度不延续到失效连接上。保留每类数据库隔离、生产调度配置和现有业务用例，不靠缩短退出超时掩盖资源关闭问题。
- 批次工具在一次操作内批量读取提交对象与历史关系，复用同一准确提交的查询结果；分支、Worktree、冲突和操作标记在元数据修改前后重新核验，不跨命令缓存外部状态。
- 交接由后端恢复入口统一准备集成数据库，保留卷保护、MySQL 容器健康、迁移目录、源码挂载和 API 健康校验。恢复使用当前启动器的 `ensure-backend --worktree`，不依赖旧目标目录的脚本版本；健康确认后才释放任务锁，备份仍保留。

### 最终候选 CI

CI 根据最终候选的完整差异区分文档、普通前端、封闭后端及全量：只有明确无关才省去另一端；权限、API、迁移、依赖、验证规则、未知文件或差异获取失败一律全量。前端适用时完整执行静态质量与构建、两个 Linux Chrome 浏览器分片；后端适用时执行完整后端质量。文档执行格式检查。

保护检查继续使用始终运行的 `Frontend quality` 和 `Backend quality`；不在整个工作流加路径跳过。汇总核对计划、候选、任务状态、完整用例清单和分片精确并集；适用任务的失败、缺失、取消、跳过、flaky 或非首次通过均不能视为成功。本轮没有启用测试例外放行制度。

受影响本地检查通过且获交付授权后，提交并推送任务分支，及时启动当前候选的 PR/CI，再进行集成及交接；不要等所有交接结束才启动 CI。等待使用状态变化或退避轮询，避免反复读取相同日志。候选变更必须重新验证适用范围，未绿不得合并；不把滚动集成分支直接合入主线。

不共享后端测试数据库、不任意并行修改全局测试状态，也不删除测试以缩短耗时。容器复用和 Spring 上下文合并需另有隔离证据，当前未启用。

## Token 与工具收敛

- 当前规则和代码已足够时不展开历史 Rollout、不访问 Notion；普通开发不查询 GitHub PR/CI。
- 精准搜索入口和必要片段；独立只读检查并行，同一状态和等价测试不重复执行。
- 成功日志只留摘要，失败再读取局部详情；浏览器只验证静态检查或接口测试无法证明的交互。
- 沿用用户当前模型与推理设置；不通过规则自动切换模型或降低推理强度来制造提速。历史 `medium` 建议不覆盖当前用户设置。

## 清理边界

- `dev:task:stop` 只停止当前任务前端和后端，不删除共享数据或备份。
- “任务完成”授权包含安全的当前任务 Git 载体清理：仅删除已证明无未提交、未推送、未合并或独立价值的任务 Worktree 及任务分支。
- 停止任务进程、恢复并核验集成环境、释放该任务锁属于必做交接；数据库、持久卷、备份、日志、依赖缓存及其他任务资产不在该清理授权内。

## 后续复盘

按小修复、页面逻辑、权限、后端和 CI 五类记录：实现、检查执行、证据检查、构建、环境交接、CI 排队及执行、合并和清理耗时。并行阶段按关键路径计算，不把各项时长相加当成用户等待时间。

2026-09-23 的历史样本显示，近期完整本地验证约 4 分钟，单次 CI 前端约 10 分钟，后端约 5 至 14 分钟；样本混有任务规模、运行环境和失败重跑差异，不代表优化后的结果。下一批同类任务比较中位数、较慢样本及失败重跑率；未实际测得前不宣称固定提速比例。
