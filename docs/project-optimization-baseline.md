# 管理后台开发效率与质量基线

最后更新：2026-08-05

本文是 `/Users/uj/Documents/Codex/装点猫/管理后台` 当前有效的开发效率、预览环境、数据库保护、验证和 Git 交付基线。被本方案替代的动态日常端口、每任务临时 MySQL、预览数据库克隆和逐轮 Git 交付不再有效。

## 目标

- 微小修改目标 2 至 4 分钟，普通局部任务默认走 4 分钟快速路径，明确跨层任务参考 5 至 8 分钟。
- 按真实风险保留权限、API、后端、数据库和运行态证据，不以时间目标替代质量门禁。
- 减少重复读取、长日志、Notion/GitHub 查询、全量验证和逐轮提交推送。

## 单任务开发循环

1. 在独立 `codex/<task>` Worktree 中完成一次范围分级、必要规则读取、Git 预检和批量定位。
2. 后续反馈复用同一上下文、分支和运行环境，只修改当前差异并运行最小充分验证。
3. 用户明确完成、验收、提交、推送或同步时，才执行一次最终审查、精确暂存、一个正式提交、一次推送和一次集成同步。
4. 任务分支是实际交付单元；`codex/integration-current` 只汇总已推送任务并检查组合结果，不在其中开发。合并 `main` 仍从已验收任务分支或 PR 完成。
5. 集成冲突涉及任务范围外文件时恢复并停止，不扩展到无关冲突修复或全项目验证。

## 固定预览入口

| 用途         | 地址                  | 内容                           |
| ------------ | --------------------- | ------------------------------ |
| 当前任务预览 | `127.0.0.1:5175`      | 完整项目基线加当前任务全部改动 |
| 滚动集成     | `127.0.0.1:5173`      | 已正式推送并汇入的任务组合     |
| Playwright   | `127.0.0.1:5174`      | 自动化页面测试                 |
| 并行对比     | `127.0.0.1:5176-5199` | 仅显式请求时使用               |
| 任务后端     | `127.0.0.1:8081-8099` | 含后端改动时使用               |

`npm run dev:task` 自动把 5175 切换到当前 Worktree。纯前端任务使用任务前端和集成后端；后端、API、Flyway 或运行配置任务使用任务前端和任务后端。无论改动涉及一个还是多个模块，5175 都展示该任务 Worktree 的完整项目。

## 唯一开发数据库

- 5173、5175、集成后端和任务后端共同使用 `zdm-platform-mysql` 中的 `zdm_admin`。
- 不按任务创建 MySQL，不克隆集成库，不做预览库与集成库的数据复制或回写。
- 用户在 5175 手工验收产生的数据直接持久化到集成库，并被后续任务继续复用。
- 页面 E2E 使用接口 Mock；后端测试使用 Testcontainers。自动化测试数据不进入集成库。
- MySQL 数据卷长期保留，容器使用 `restart: unless-stopped`；Docker Desktop 启动后自动恢复 MySQL。

### 数据库保护

- Flyway 文件变化自动进入保护流程；批量删除、清空或破坏性导入等非迁移任务显式使用 `--database-risk`。
- 任务后端启动前检查 Flyway 失败记录和其他共享数据库任务后端；存在其他写入者时停止并报告，不批量停止。随后暂停当前任务与集成后端，创建并校验 gzip 备份。
- 集成数据库可能领先于 `main`；启动器合并集成分支与当前任务的迁移目录供 Flyway 校验，同版本不同文件或同文件内容冲突立即停止，不使用忽略迁移规则。
- 保护期间禁止切换到其他任务；迁移或启动失败时保留备份和现场，不自动恢复。
- 表或字段删除、大批量数据删除、数据库恢复必须先报告影响并取得用户明确确认。
- 数据库结构只通过 Git 中的 Flyway 迁移交付，禁止只执行手工 DDL。
- 任务同步集成分支后运行 `npm run dev:task:handoff`；集成分支包含任务提交且 8080 健康后才释放数据库锁，备份继续保留。

本方案面向当前单人串行开发。未来两人或多人并行修改数据库结构时，必须重新评估并引入独立数据库或冻结验收方案，不能直接沿用共享写入模型。

## 验证路由

- 文案、规则、脚本别名：检查差异和格式。
- 低风险样式、小交互、列顺序和字段位置：`check:changed`，必要时只补一个指定 E2E，禁止完整 `verify`。
- 中风险页面、表单、路由和服务层：变更文件检查加受影响单测或 E2E。
- 登录、权限、API、后端、迁移和数据状态：相关前后端测试及真实运行态证据；边界不明时升级完整检查。
- 发布、正式合并或高风险回归：`verify` 或 `verify:local`。
- 已知 Docker、本地监听和系统 Chrome 调用首次即走有效的最小授权路径，不先制造一次必然失败。

## Token 与工具收敛

- 当前规则和代码已足够时不展开历史 Rollout、不访问 Notion；普通开发不查询 GitHub PR/CI。
- 精准搜索入口和必要片段；独立只读检查并行，同一状态和等价测试不重复执行。
- 成功日志只留摘要，失败再读取局部详情；浏览器只验证静态检查或接口测试无法证明的交互。
- 默认使用 `medium` 推理；只有复杂权限、架构、安全、疑难故障或真实范围升级时暂停并说明需要 `high`。

## 清理边界

- `dev:task:stop` 只停止当前任务前端和后端，不删除共享数据或备份。
- 提交、推送、集成同步和数据库交接完成后，先报告交付，再单独询问是否清理任务容器、旧版临时 MySQL、备份和运行日志。
- 未明确确认时一律保留；永不把集成 MySQL、持久卷、集成数据、代码、分支或依赖缓存作为普通任务清理对象。

## 保留与移除

保留：独立 Worktree、固定 5175、必要的临时对比端口、任务后端、Maven 缓存、增量验证、一次 Git 交付、滚动集成检查和高风险完整门禁。

移除：动态日常预览地址、每任务临时 MySQL、预览数据库克隆与双向同步、前端改动也启动完整环境、每条反馈提交推送、低风险完整验证、范围外集成冲突修复和重复成功日志。

## 后续复盘

按小修复、页面逻辑、权限、后端和 CI 五类持续记录耗时、Token、工具调用和验证结果。连续样本显示某一规则降低质量或未减少往返时，再更新本基线；不因单次体感放宽数据和权限门禁。
