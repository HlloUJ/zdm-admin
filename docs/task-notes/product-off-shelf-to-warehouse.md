# 成品现货、配件、大板商品下架流程调整 PRD

- 版本：V1.1，2026-10-28，用户已确认实施。
- 批次：`product-off-shelf-to-warehouse`。
- 目标：取消已下架 Tab 和商品状态；下架直接回仓库并保留整改依据；已上架可直接删除至回收站。
- 交付范围：本地实施、验证、预览及明确授权的测试数据清理；未获得正式推送、合并或生产发布授权。

## 适用端与保留边界

| 模块         | 供应链端 | 运营端 | 门店端                                 |
| ------------ | -------- | ------ | -------------------------------------- |
| 成品现货管理 | 调整     | 调整   | 调整                                   |
| 配件管理     | 调整     | 调整   | 调整                                   |
| 大板管理     | 调整     | 调整   | 清理实际存在的关联数据，不新增独立页面 |

保留既有组织归属、身份、数据隔离、编辑字段、发布入口、库存、价格及上下游恢复规则。不增加批量删除、整改审批或新的整改状态。

## 状态与流程

保留仓库中、已上架、已售完、回收站，按各端现有能力和权限显示。

| 场景           | 新流程                              |
| -------------- | ----------------------------------- |
| 下架或批量下架 | 已上架 → 仓库中，填写下架原因及说明 |
| 已上架直接删除 | 已上架 → 回收站，无需先下架         |
| 仓库删除       | 仓库中 → 回收站                     |
| 回收站恢复     | 回收站 → 仓库中                     |
| 重新上架       | 仓库中 → 已上架，通过原有校验       |

- 供应链手工创建、运营接收供应链上架商品、门店从商品池选入的入口保持。
- 取消商品及供应链来源的 `offShelf` 状态；该标识仅可表示下架动作，不能作为新接口的商品状态。
- 删除已下架 Tab 及其详情、恢复、批量恢复、删除入口。回收站相同操作保留。
- 保留已有已上架编辑能力，不要求所有编辑先下架，不强制下架后修改字段才可上架。
- 下架、必要日志及联动保持事务一致性，不能连续调用旧下架和恢复接口模拟新流程。
- 普通删除进入回收站，保留恢复所需商品及媒体，不立即物理删除。
- 各端继续按原有批量事务和失败反馈处理，不静默跳过失败商品。

## 下架信息

- 每端分别保存最近下架原因、说明、操作人及实际发生时间，不混用本端与上游原因。
- 仓库列表显示最近下架原因及说明，编辑入口只读显示下架依据；从未下架显示“—”。
- 普通仓库编辑不清除原因。重新上架后结束本次待处理展示，历史下架日志继续保存。
- 再次下架更新最近信息，各轮日志独立保存。回收站恢复不伪造一次下架。
- 创建时间不被覆盖；下架回仓库更新当前状态操作时间，按原有状态活动规则排序。
- 沿用现有原因选项、必填条件、文本长度限制及时间接口契约。

## 上下游联动

- 供应链下架继续触发运营失效，以及成品现货、配件适用的门店失效。
- 运营下架继续触发适用的门店失效。
- 已上架直接删除执行删除至回收站对应的联动。
- 门店操作不反向改变上游商品。
- 来源重新上架不自动复活失效下游记录，保留既有清理、重新入仓和挑选规则。
- 失效原因、时间、快照、媒体引用和操作限制保留。仓库状态不代表来源恢复有效。
- 自动售价待补齐引起的既有停售同样改为进入仓库，保留原来的原因、价格提示和日志。

## 日志

| 操作           | 操作类型                        | 状态变化               |
| -------------- | ------------------------------- | ---------------------- |
| 下架回仓库     | OFF_SHELF／下架                 | 已上架 → 仓库中        |
| 已上架直接删除 | DELETE_TO_RECYCLE／删除至回收站 | 已上架 → 回收站        |
| 回收站恢复     | 原有恢复类型／放回仓库          | 回收站 → 仓库中        |
| 上架           | SHELF／上架                     | 仓库中 → 已上架        |
| 编辑           | 既有编辑或专项类型              | 实际字段差异及实际状态 |

一次下架只记录一次本端下架事件，不补恢复事件；直接删除不伪造下架。批量操作逐商品记录。上下游分别保存真实业务端、主体和状态变化，历史日志不随后续编辑改变。保留下架及回收站恢复的查询筛选。

## 功能目录与权限

- 删除已下架 Tab 和专属资源，保留已上架下架及批量下架。
- 已上架新增独立删除资源，目录、页面和后端校验一致。
- 继续使用统一目录，保持终端、角色候选及数据范围边界。
- 不自动授予角色新增权限，也不将旧已下架删除权限转换为已上架删除权限；用户手工配置。

## 双环境数据重置

集成、长期预览两个环境分别核实数据库、媒体卷及写入方后，清空三个模块供应链、运营、门店实际存在的商品及日志数据。

清理商品主记录、规格、商品属性填写值、商品级价格、门店选品与售价、下架记录、状态活动、操作日志、失效快照和对应媒体引用；不做历史归并或旧流程兼容。

保留价格配置规则、门店级别、分类、模板、属性定义、供应商、大板字典、账号、组织、角色及其他基础配置。商品具体价格清理，计算价格的基础规则保留。其他模块、容器及卷不删除。

执行前查外部引用。范围外业务引用冲突时保留现场，不扩大清理。停止目标写入，确认无竞争写入方，备份并持有数据库保护锁后执行；失败不自动重建或恢复数据库。

## 媒体及备份

- 清理目标商品的主图、附图、视频、详情描述媒体、视频封面、缩略图及日志和快照派生文件。
- 删除业务引用后重新检查全平台引用。仅处理可证明专属的文件；工艺、客户跟进、基础配置及其他保留业务共用媒体保留。
- 使用平台媒体存储的安全路径和引用保护机制；不得清空媒体目录或卷。外部链接仅移除系统内引用。
- 无法证明归属的无引用文件保留并报告；不猜测其业务来源。既存缺失文件单独记录。
- 只含三个模块旧测试商品、日志、专属媒体的备份，核实后可删除；混合备份、未知备份保留。
- 本次清理前的新数据库及媒体恢复备份保留至新流程验证通过，后续单独收尾。
- 结果需核对物理文件及非目标配置，不能以清理任务入队视为完成。

## 验收

1. 所有适用端取消已下架 Tab 与状态，接口拒绝取消状态。
2. 单条、批量下架直接入仓，下架信息可见且普通编辑保留。
3. 原上架校验、已上架编辑、售罄与回收站行为有效。
4. 已上架按权限直接删除，只发送一次删除业务请求。
5. 下架日志为已上架到仓库，没有额外恢复或伪造下架。
6. 原下游失效、快照、媒体及来源日志有效，来源恢复不自动复活下游。
7. 创建时间保持，当前状态时间和排序正确。
8. 统一目录、页面和后端权限一致，无自动角色授权。
9. 两个环境目标商品和日志清空，无无效关联；保留配置和非目标引用的摘要一致。
10. 专属媒体实际清理，共用及未知媒体保留并说明，备份按范围保留或删除。
11. 两个环境最终健康；预览证明任务 Worktree、分支、模式、API 与代理身份。

按项目规则执行受影响单测、接口、权限与现有自动化 E2E；不新增主动人工浏览器验收。实际进度与验证、清理回执独立记录，不将本文视为完成证明。
