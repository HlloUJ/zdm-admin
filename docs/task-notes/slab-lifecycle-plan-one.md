# 大板管理：方案一实施边界

## 已确认行为

- 仅供应链和运营管理平台，不涉及门店；沿用既有权限和数据范围。
- 供应链下架、删除至回收站、彻底删除，使已有运营记录永久失效。
- 运营记录保留原列表位置；遮罩仅提供详情和按权限彻底删除，禁止其他业务操作。
- 后续下架或删除更新失效原因；供应链重新上架不恢复旧记录，不生成无实际业务变化的运营上架日志。
- 运营先删、来源后上架：来源上架后重新进入运营仓库。
- 来源先上架、运营后删：删除旧记录后重新进入运营仓库。
- 新入仓使用当前成本及价格配置计算，旧手工价格不继承；价格配置同步跳过失效记录。
- 失效时冻结商品、价格和媒体引用；旧记录删除日志保留旧名称，新入仓日志保存新快照。同一商品 ID 的历史日志继续保留。
- 来源彻底删除后不能重新上架同一商品；两端均彻底删除才释放商品业务引用，历史日志媒体继续按既有规则保留。

## 迁移与兼容

V141 增加运营失效原因、时间及 JSON 快照，回填当前已失效的历史记录。
迁移前没有保存的快照不伪造；详情明确提示历史快照缺失，当前资料不代表失效时资料。
成品现货的既有业务规则不改变。未新增菜单、权限资源、跨组织数据范围或 CSS 规范。

## 验证覆盖

专项覆盖两种删除/恢复顺序、来源价格不变及改变、失效期间旧名称/价格/媒体、原因递进、禁止业务操作、旧记录删除与新入仓日志、自动价格配置同步冻结。
执行后端全量测试和静态质量检查，以及大板协同、价格编辑器、发布布局自动化。具体执行报告留在本任务 `.task-verification/`，不将失败尝试覆盖成成功。

## 同批已有界面调整

供应链大板发布页移除面包屑栏；编辑页保留。供应链大板创建快照中的未填写字段显示 `-`。

运营大板供应商筛选右边与品种对齐；来源操作日志沿用成品现货文案。来源恢复后彻底删除旧记录，列表即时重新加载并显示新入仓记录。
