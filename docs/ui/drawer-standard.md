# 抽屉全局样式规范

状态：2026-10-23用户确认。覆盖运营端、供应链端、门店端及其他现有和后续业务端。以后新增或调整抽屉时默认必须遵守本规范，只有用户明确提出特殊要求时才允许例外；开发者不得自行以方便实现、历史页面或其他模块做法作为例外依据。

本轮只沉淀规范，不修改页面代码，不代表存量抽屉已经迁移。未纳入当前任务的存量页面不自动改造；后续新增或调整抽屉时须按本规范实现。

## 组件与外观

统一使用TDesign原生Drawer，默认从右侧打开。保留官方遮罩、边框、字体、颜色、间距及动效；通过官方公开属性和插槽实现，不另做抽屉皮肤，不通过自定义CSS、内联样式、内部类覆盖或主题变量重绘官方视觉。官方组件无法表达的必要业务布局按全局UI规范处理，不构成另设皮肤的授权。

## 结构、标题与滚动

- 固定采用顶部标题栏、中央内容区、底部操作栏三个区域。标题和操作栏不随正文滚动；内容超高时只滚动正文，复用原生结构，不额外嵌套整层滚动容器。
- 标题只在原生顶部栏出现一次，正文不重复展示同名标题。
- 不默认增加副标题或说明栏。确有必要的说明放在相关内容附近；范围说明、字段提示等有业务作用的内容不因去除重复标题而一并删除。

## 操作栏与按钮

- 表单提交和整体业务操作统一放在原生底部操作栏，不放在正文顶部。字段旁的新增、删除等局部操作保留在对应字段附近。
- 默认右侧抽屉沿用TDesign原生布局：底部靠左，主操作在前、取消在后。不得为统一成Dialog布局而改成右对齐或交换顺序。
- 新增使用“确认新增”，编辑使用“确认保存”，业务操作使用“确认＋操作名称”；批量操作按全局执行按钮命名约定保留“批量”。主题使用既有功能映射，加载、禁用及权限条件按业务原规则执行。
- 取消关闭抽屉，不提交本次填写。校验失败时保持抽屉打开，并按全局表单校验反馈标准展示错误；不因改用原生确认事件而绕过校验或提前关闭。

## 宽度与正文布局

普通内容使用原生默认宽度。多列表单、规格矩阵等需要更宽空间时，通过官方size属性适配内容，不将某个页面的宽度作为全局默认，也不以本规范统一改写已有字段列数和顺序。

正文继续遵守[表单样式规范](./form-style-standard.md)、[字体标准](./typography-standard.md)、[占位文案标准](./placeholder-standard.md)及[表单校验反馈标准](./form-validation-standard.md)。抽屉不另设一套字段间距、控件外观或错误提示规则。

## 按用途显示操作栏与关闭入口

编辑、填写和业务操作抽屉默认显示底部操作栏。纯详情、只读查看抽屉可隐藏底部操作栏，保留顶部关闭入口。

顶部关闭按钮、遮罩和ESC使用原生能力。已有未保存提醒、关闭限制等业务保护继续保留，不因统一外观而绕过或移除；如需改变这些业务行为，须另有明确授权。

## 实施与例外边界

- 本规范适用于所有业务端，不按运营、供应链或门店分别采用不同默认布局。
- 用户明确批准的特殊要求仅在其指定范围内生效，不扩散为其他抽屉的默认做法。
- 新增或调整抽屉前读取本规范，核对实际共享使用方；实施后检查标题唯一、按钮区域与顺序、正文滚动及原有提交、取消、校验和关闭保护。
- 规范确认不等于页面迁移或批量改造授权。本次不改变页面标题、字段、权限、接口、数据和业务处理逻辑，也不自动调整存量页面。
