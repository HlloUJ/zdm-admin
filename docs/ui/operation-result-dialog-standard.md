# 操作结果提示弹框全局标准

确认日期：2026-10-30。适用于所有业务端及后续新增同类功能。本文定义用户已确认的项目布局规则，不将其表述为 TDesign 官方默认尺寸。

## 适用范围与边界

仅适用：业务操作已经执行，系统返回结果，通过弹框展示结果并让用户确认关闭。内容可以是纯文字、任意列数表格或混合内容，不局限于批量上架、两列表格或失败结果。

以下不适用：新增／编辑表单、提交操作前的执行确认、操作前校验阻断、详情查看、日志历史、图片视频预览、商品中心及其他工作界面。Toast、字段校验和页面内提示保持原有形式，不因本规范转换为弹框。

先生成业务产物、再展示供复制或使用的界面，应在清单中单独说明业务交互，避免仅凭“关闭”按钮便将其当成普通结果提示并擅自重构。

## 弹框宽度

| 项目         | 规则                                                               |
| ------------ | ------------------------------------------------------------------ |
| 宽度         | 根据正文内容所需宽度自适应，不固定为表单宽度                       |
| 常规最小宽度 | 480px                                                              |
| 最大宽度     | `min(960px, 90vw)`，不得超过此上限                                 |
| 窄视口       | 最大宽度优先；有效最小宽度为 `min(480px, 最大宽度)`                |
| 计算边界     | 最小／最大宽度均指弹框外框；正文可用宽度须扣除官方原生内边距及边框 |

短内容受最小宽度约束；长内容推动弹框变宽，达到最大宽度后正文换行。不通过扩大到全屏、缩小字体或压缩内边距容纳内容。

纯文字按正文所需宽度计算；混合内容按各内容块所需宽度的最大值计算，再应用上述上下限。

## 表格列宽与换行

1. 表格铺满弹框正文可用宽度，不强制各列均分。
2. 表头不参与正文内容宽度需求计算；单列表头保持一行所需的宽度，加官方单元格内边距和边框，作为该列最小宽度。
3. 各列按正文内容需求分配宽度；短列省下的宽度可分给长列。因此均分宽度不是单列硬上限，也不另外规定固定的单列最大像素值。
4. 所有列宽合计受弹框正文可用宽度约束。达到弹框最大宽度后，在保留其他列最小宽度的前提下分配剩余空间，超出分配宽度的单元格内容换行。
5. 长商品ID、连续英文、URL等无空格字符串同样必须换行；不得产生横向滚动，不截断、不省略、不隐藏结果。
6. 当前不引入极端多列场景的特殊展示规则，不自行改成卡片、分组或其他业务布局。

表格铺满正文不代表弹框必须达到最大宽度：弹框先按内容和最小宽度确定实际宽度，表格再铺满该实际正文区域。文字、表格和其他内容块均不能撑破弹框上限。

## 高度与阅读

内容超过视口可用高度时，正文区域纵向滚动；标题、关闭入口和原有确认操作保持可见、可用。弹框不得溢出视口。正文禁止横向滚动，不能用省略号或只展示部分结果代替完整内容。

不在本规范另行增加未经确认的固定高度数值。后续实现须基于可用视口高度与官方结构约束正文区域。

## 官方外观与全局规范

- 基于项目登记版本的 TDesign 原生 Dialog、Table、Typography、Button 及既有公共封装；官方来源沿用[全局规范](standard.md)及 `official-sources.json`。
- 字体、字重、字号、行高和语义颜色遵守[字体规范](typography-standard.md)，使用官方完整字体变量，不新增硬编码字体皮肤。
- 弹框内边距、分区间距、表格单元格内边距、按钮、边框、圆角、阴影及动效沿用官方及既有全局规范。本文不重定义这些数值。
- 允许的专项布局仅限已确认的内容宽度分配、换行和溢出管理；不得借机覆盖原生组件皮肤或修改主题变量。
- 标题、文案、按钮名称与主题、关闭行为及原有复制等业务交互保持现状；确认仅用于确认结果，不重新执行已经完成的操作。

## 复用与存量实施边界

后续新增或经授权迁移的同类结果弹框，应通过公共入口集中提供该专项布局能力，不逐页复制尺寸和换行规则。该能力必须显式接入，仅作用于操作结果弹框，不能改变新增／编辑及其他弹框的默认表现。

当前 `AdminDialog` 通用默认宽度480px、`AdminFormDialog`、`AdminConfirmDialog` 及其使用方保持不变。建立规范不等于已经实现公共布局能力，也不自动授权迁移全部存量页面、建立新守卫或调整业务数据、权限、日志及接口。

本轮仅更新规范、完成源码扫描并列出清单；存量迁移对象与实施方案另行确认。现状见[扫描清单](operation-result-dialog-audit.md)。

## 后续实施验收要求

- 短文字遵守最小宽度，长文字按内容增长且不超过最大宽度；窄窗口下最大宽度优先。
- 两列和多列表格均按正文需求分配宽度，表头作为最小宽度；短列空间可用于长列，表格铺满正文。
- 达到上限后普通文字和连续字符串均换行，无横向滚动、截断或结果丢失。
- 混合内容、窗口缩放及长结果列表遵守相同边界；正文纵向滚动时标题和操作仍可用。
- 官方字体、边距、组件外观与既有交互不变；新增／编辑和操作前确认不受影响。

上述为后续迁移验收要求，不代表本轮已修改页面或运行相关交互验收。
