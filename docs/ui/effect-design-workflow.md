# 效果图设计与同源开发工作流

状态：2026-11-05 用户确认；适用于装点猫管理后台。本文件是效果图协作流程的唯一维护入口，AGENTS 与项目 Skill 只提供发现入口和摘要。

## 触发与数量

- 用户说“帮我出一份效果图”或明确同义的效果图请求时启用。默认 **5 个方案**；“一份”指一次设计任务，不代表一个方案。用户明确指定其他数量时按该数量执行。
- 普通“UI 设计”“页面设计方案”、缺陷修复、字段调整不自动进入五方案流程；明确同义请求按效果图意图识别，不做机械字面匹配。
- 同一次任务中的修改、比较、选版及获准实施沿用此流程，不必重复触发，也不自动每轮重出五个方案。

## 设计角色与边界

以 UI 设计师角色解决业务信息的视觉表达。TDesign 是视觉基础，完整模板结构不是设计上限。

- 保持官方基础组件外观，以及系统既有颜色、字体、圆角、阴影、图标和交互语言；不重绘按钮、输入框、表格等基础组件皮肤，不另造全局主题。
- 允许为指定页面自主设计分区、空间比例、排列、视觉重点和信息层级，编写必要的局部布局 CSS；优先使用官方组件、公开接口、项目公共实现及设计变量，不为每处必要布局重复询问。
- 现有查询、表单、抽屉、字体等专项规范仍有效；需要突破时，在方案中列出对象、拟改行为、理由和范围，待用户明确确认该差异。一般选版不默许未披露的规范偏离。
- 名称、字段含义、必要内容、权限、数据范围、入口及操作流程保持既有约定。设计发挥不授权业务变化，不迁移其他页面、不修改官方来源快照。

## 第一阶段：五个轻量展示方案

1. 利用用户给定内容及当前项目事实明确页面范围、必要内容、保留约定和评审视口。可推断的条件直接说明；缺失信息会改变业务含义时先询问，不编造正式规则。
2. 五方案使用相同的业务内容、代表性模拟数据、视口及系统导航条件；未授权时不改变顶栏、侧栏或菜单。默认 PC 管理后台，记录本次实际 CSS 视口尺寸，不把某个固定尺寸推广为全系统标准。
3. 五方案体现布局、信息组织或重点表达的实质差异，不靠换色凑数，不通过删减必要内容美化方案。每个方案附设计重点、适用场景和取舍，并给出推荐理由。
4. 沿用项目 Vue 3、TDesign、公共样式及字体资源构建展示层；只做评审所需结构、样式、模拟数据与关键状态。必要交互仅为表达设计，不提前接真实接口、开发完整权限/校验/流程，不做五套业务实现。
5. 共用组件、素材、数据和公共样式，只保留必要差异；不为共享搭建复杂配置引擎，不引入另一套 UI 库或临时重绘官方组件。采用后应能直接继续开发。

## 渲染与交付

- 效果图由对应的真实展示源代码直接渲染；不得用 AI 图片替代精确页面基准，不修饰截图制造源代码无法呈现的效果。图片生成可按需用于页面素材，素材仍须进入展示源文件。
- 效果图请求包含专用设计预览的必要启动、渲染、截图及核对授权，是默认省略浏览器验收的限定例外；不读取或操作用户当前标签页，不扩展为无关页面人工验收。
- 渲染工具不可用时如实报告已保存内容与缺口，不能把源码、描述或未经核对的图像称为已完成效果图。
- 遵循现有批次及预览隔离规则，不接管其他任务的 5175，不为纯展示隐式启动共享真实后端；需要独立设计预览时使用已核实的隔离入口，不自行改变长期预览、API 或数据源。
- 每次首轮交付含五个编号稳定的实际效果图、简短比较与推荐、对应展示源文件/本地查看入口、模拟内容与必要假设、尚待确认的规范差异。组合总览可辅助比较，不能替代清晰可读的各方案图。

## 第二阶段：选版与保留基准

- 用户选定后，保存准确方案 ID/版本、展示源文件、共享依赖和样式、字体图标素材、依赖锁定信息、渲染启动方式、CSS 视口、浏览器/缩放/设备像素比、模拟数据、页面状态与对应效果图。
- 采用现有 Git 和任务资产机制保存可找回版本及查看入口，不依赖聊天中图片、截图临时地址或未保存的运行状态；不另造一套版本系统。仅有提交 SHA 不足以覆盖未提交素材，必须保存实际可复现内容。
- 后续修改形成新版本，不覆盖已确认基准。用户要求组合多个方案时先形成合成版供确认，不在正式开发时自行拼接。
- 选版只确定视觉，不自动授权接业务或正式交付。用户同时明确“按该版实施”时可直接进入下一阶段，不追加重复确认。

## 第三阶段：同源开发

- 获得对应页面实施授权后，沿用选定版本的展示结构、组件、样式与素材，添加数据绑定、事件、接口、校验和权限；不重新写一套页面，不看图估算字号、颜色和间距。
- 适当分离展示与业务逻辑，接真实数据不应成为重新设计的理由。生产页面优先复用项目公共入口和能力；必要适配不得破坏已确认视觉或既有业务约定。
- 在选定设计体系内补齐长文本、多数据、空数据、加载、错误、禁用及权限差异等实际需要的状态。前期仅展示影响选型的关键状态，其余在选版后按业务需要完成。
- 实现确实需要改变已确认视觉时，先说明现状、必要性、影响与替代方案，取得该变化的确认；不静默修改，不用旧版本覆盖用户后续改动。

## 验收与规则衔接

- 视觉验收以准确选定版本为依据，业务验收以已确认需求和既有规则为依据，两者都要满足。
- 相同环境、视口、数据和状态下应保持相同渲染结果；差异先排查源代码、样式、字体、依赖及环境，不笼统接受“还原总有误差”。不同环境的字体抗锯齿等差异须具体说明，不以此接受可修复布局差异。
- 不同屏幕与内容状态按已记录的适配规则判断，不承诺跨环境、跨内容逐像素相同。正式开发不默认扩展为所有视口全量截图；以同源保留、适用自动化检查和用户反馈为依据，进一步人工浏览器验收须有对应授权。
- 定制布局是本模式的已批准设计空间；专项规范偏离须明确批准。接入生产源码前，将准确页面与获准差异登记为项目扩展并核对相关守卫/测试消费者，不冒称官方原样模板。
- 现有守卫无法表达已批准方案时，保留设计成果，按准确范围补齐最小支持及对应验证；禁止关闭全局守卫、放宽断言、覆盖官方或原业务基准来换取通过。未获批准的规范差异不能通过工程登记变成授权。
- 本轮只建立工作约定，不改验证器或提前开放任何页面豁免；后续定制方案在具体任务中按实际对象处理。无关开发继续遵守原规范。

## 授权含义

| 用户动作               | 授权范围                                                                  |
| ---------------------- | ------------------------------------------------------------------------- |
| 确认本工作流           | 沉淀工作规则，不自动启动某个页面                                          |
| 请求效果图             | 按默认五方案制作展示层并渲染专用设计预览；明确数量优先                    |
| 修改、比较、选定效果图 | 调整或确定视觉版本，不自动接业务、不自动重出五版                          |
| 明确实施选定版本       | 在该范围内复用展示代码接功能，业务变化仍按具体授权执行                    |
| 提交、推送、任务完成等 | 按现有 Git 与交付授权规则处理；选版和实施本身不额外授权正式交付或生产发布 |

对跨任务有效的改动同步维护 AGENTS 发现入口、UI 规范和项目 Skill，避免只在聊天或孤立文档中存在。本工作流限定当前项目，不自动改写用户级 Skill 或其他项目规则。
