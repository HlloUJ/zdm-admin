# 列表查询区全局标准

状态：2026-10-15 用户确认。以已验收的供应链端大板管理查询区为依据，登记为官方 TDesign 视觉之上的项目布局扩展；不是官方模板原样复刻。

## 适用范围与唯一入口

- 新增普通列表查询区必须使用 `@/components/foundation` 导出的 `AdminListPage`，默认 `adaptive-grid`。禁止新模块选择 `inline`、`official-grid`，复制筛选布局、定义列数或添加页面局部覆盖。
- 唯一样式实现：`src/components/foundation/official/query-layout.css`。已验收的大板页和公共入口共用此文件，禁止各维护一份。
- 2026-10-15 用户确认全局推广：现有普通列表、商品中心弹窗及操作日志查询区统一接入公共样式。`inline`、`official-grid` 仅兼容既有显式使用方。
- 编辑表单、SKU 矩阵及没有查询／重置按钮的单控件即时搜索不接入查询布局；缺少支持的业务字段应先扩展公共入口，不能在新页面自行建立另一套布局。

## 固定规则

| 项目                       | 必须遵守的值或行为                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------- |
| 条件区／按钮区             | 10:2，占整个可用宽度；外层不另加列间 gap                                               |
| 查询与重置                 | 位于右侧按钮区、首行对齐、右对齐；按钮间距 8px，沿用官方原生尺寸                       |
| 标签                       | 80px、右对齐、冒号；不按文字长度修改标签宽度                                           |
| 条件数量 1～3              | 最多三列基准，剩余位置留空，不能拉伸成一列或两列铺满宽屏                               |
| 条件数量 ≥4                | 最多四列，多出的条件自动换行；不再采用五列                                             |
| 列宽计算                   | 根据条件区实际宽度计算；每列至少 238px，即 80px 标签＋134px 控件＋左右各 12px 列内边距 |
| 宽度不足                   | 自动减为三、二或一列；正文仍沿用项目既有最小宽度和侧栏响应规则                         |
| 最后一行                   | 与前面各行等宽、按原字段顺序从左到右排列；不单独拉伸                                   |
| 横向间距                   | 相邻列内容间距 24px；行容器左右 -12px、列左右各 12px                                   |
| 两行控件之间               | 24px；由栅格行间距实现，表单项底部间距为 0，不能重复叠加                               |
| 最后一行到下方业务操作按钮 | 24px；筛选区内部无末行底部留白，由外层区域间距承担                                     |
| 控件外观                   | TDesign 原生字体、高度、颜色、边框、圆角及状态，不另设紧凑皮肤                         |

这里的“最多四列”不等于所有窗口都固定四列，也不按浏览器宽度写一组各页独立的断点。列数取决于条件区实际可用空间和当前可见条件数。Tab 切换或条件因权限减少时，使用实际渲染数量重新排列。

## 窄屏共用布局

2026-10-22 用户批准修复所有查询区遮挡，同时保留桌面布局和业务逻辑。以下为窄屏例外，统一在 `query-layout.css` 实现：

- 视口宽度 ≥992px 时保留原10:2分区、列宽计算、字段位置及按钮位置。
- 视口宽度 ≤991px 时，条件区占满可用宽度，查询／重置按钮在下一行右对齐；条件区与按钮区间距24px，按钮间距8px，空间不足时按钮换行，不压缩原生按钮。
- 字段继续按原顺序自适应减列，标签保持80px；控件允许在窄容器内收缩，不再让134px最小宽度挤出容器。保留原生字体、高度、颜色及交互。
- 普通页面、商品中心弹窗、操作日志抽屉共用这组规则。无分页的查询页面同样适用；带侧栏的查询工作区复用公共响应式面板入口，在窄屏上下排列。
- 不改变字段、查询／重置事件、API、筛选时机、权限、默认值或分页状态。桌面与窄屏均须验证查询区、分页和遮挡情况。

## 共用日志变体

2026-10-15 用户确认日志查询区变体：共用同一份 `query-layout.css`，仅将最多列数从普通列表的四列降为三列，不维护第二套样式。

- 未来日志查询优先复用 `ProductOperationLogTemplate`。该公共入口自动声明 `data-query-layout="log"`。
- 其他明确登记的日志查询容器使用同一标记，列数仍按实际可用宽度减少为二或一列；不是窄窗口强制塞三列。
- 10:2 分区、80px标签、134px控件最小宽度、横向24px、两处垂直24px、按钮样式和右对齐全部与普通列表共用。
- 不改变日期筛选、输入、清空、查询、重置、分页、详情及全屏交互。

## 业务与交互边界

- 布局组件只更新输入草稿并发出查询、重置事件，不自行改变 API、筛选含义、权限、默认值或查询时机。
- 沿用页面既有字段顺序、文案、占位文字、可清空与手工输入能力。需要新增业务交互时单独确认。
- 普通页面点击“查询”应用条件；“重置”清空条件并重新查询，由业务处理函数实现。输入或换列不自动发起查询，不添加展开／收起。
- 大板管理移除“下架时间筛选”是独立业务决定，不代表其他模块必须移除日期筛选。
- 自定义字段使用 `AdminListPage` 的 `filter-字段key` 插槽；插槽只提供控件，表单项、标签和栅格由公共入口提供。表格列仍使用原有插槽。

## 新模块接入与验收

```vue
<AdminListPage
  v-model:filter-values="filterDraft"
  :filters="filters"
  :actions="actions"
  :table-props="tableProps"
  @search="applySearch"
  @reset="clearAndSearch"
/>
```

1. 实施前读取本文件和 `docs/ui/standard.md`；直接配置公共入口，不重新设计样式。
2. 核验 1、2、3、4、7 个条件，以及宽窄容器、Tab／权限变化、末行不足一整行等情形。
3. 检查 10:2、最多四列、末行等宽、两处 24px、按钮右对齐，并确认没有表单底部间距叠加。
4. 执行 `check:ui-templates`、受影响变更检查和公共查询区布局自动化。新增页面选择旧布局或复制布局应被门禁拒绝，不能靠修改预期接受偏差。
5. 新字段无法表达时，先说明公共入口缺口并扩展、验证入口；不以实现方便改变业务约定。

标准不保证所有开发一次零缺陷；公共实现和自动门禁用于让每次实现有同一依据，并在交付前发现偏差。

## 组合搜索字段（统一规则）

组合搜索是全局查询标准的一类字段，不属于页面外的特殊样式。标题使用“商品”“大板”等简短名称，输入框显式配置完整搜索范围作为占位提示。80px标签列、24px行间距、10:2分区和列数规则全部保持一致；不换行、不扩宽标签、不缩小字体。

| 页面                 | 标题 | 占位提示               |
| -------------------- | ---- | ---------------------- |
| 供应链、运营成品现货 | 商品 | 请输入商品名称/ID      |
| 门店成品现货         | 商品 | 请输入商品名称/ID/编号 |
| 供应链、运营大板     | 大板 | 请输入大板名称/ID/编号 |

未来模块通过 `AdminListPage` 的 `ListFilter.searchScope` 显式填写范围，例如 `{ key: 'keyword', label: '大板', searchScope: '大板名称/ID/编号' }`。公共入口生成完整提示；不配置时仍按普通字段的“请输入＋标题”。兼容页面的对应输入框使用 `data-query-search-scope` 声明同一范围，标准守卫核对其提示。不根据标题或业务类型自动推断，不因此扩展实际搜索能力。

普通字段、编辑表单、选择控件仍遵守原占位标准。此前“仅调整三端主列表、日志和弹窗暂保留”描述的是早期实施范围，不是永久样式例外。2026-10-23用户确认将所有业务端的抽屉查询及操作日志纳入组合搜索规则：短标题配合显式配置的完整搜索范围提示。公共列表使用ListFilter.searchScope，公共日志或其他兼容查询入口须消费调用方显式声明且真实支持的完整范围，不仅按短标题生成普通占位文案；不推断或扩展搜索能力，不改其他业务标题、表头及请求语义。

查询／日志抽屉的容器、宽度、滚动及操作位置遵守[抽屉全局样式规范](./drawer-standard.md)。查询和重置保留在查询区、行级详情保留在表格，不因整体提交按钮放底部而将这些局部操作搬到底部。最初确认阶段仅更新规范，该历史说明不构成日志抽屉的永久豁免；实际接入及待办以抽屉专项规范的实施记录为准。后续检查须覆盖全部共享业务端的显式范围提示及实际生效的查询样式，不以容器合规或测试总数代替逐项验收。
