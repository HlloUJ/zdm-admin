# 全局表单校验反馈标准

状态：2026-10-16 用户批准全系统统一；现有和未来新增模块均遵守，不区分简单、复杂或长短表单。

## 统一规则

- 提交校验失败，所有错误字段同时标红，在字段下方显示具体错误；只弹一次固定汇总Toast“表单校验未通过，请检查标红字段”，自动定位首个错误字段。
- 具体提示说明如何修正，例如“请输入商品名称”“请选择产地”“同级分类名称不能重复”。不得以第一条错误作为汇总提示，也不得仅标红或仅弹Toast。
- 输入、失焦时只更新既有字段反馈，不弹校验Toast、不滚动；不改原有校验触发时机和规则。
- 提交失败、网络或服务异常保留原Toast。未选操作对象、没有可用配置、等待上传、至少保留一条规格等无字段可定位的操作前置提醒保留原交互。
- 不新增校验器、正则、必填条件、数量上限、价格阈值；不改默认值、权限、API、提交接受或拒绝条件、保存和取消。只读字段不新增校验。富文本内容、上传和附件业务实现不变。

## 公共实现

1. 原生Form优先使用现有rules和FormItem name，保持showErrorMessage开启。重复名称等已有本地错误用setValidateMessage附到字段。
2. 手工反馈复用 `src/utils/formValidation.ts`：`fieldFeedback`、`requiredFieldFeedback`提供原生status、tips和 `t-is-error`；`useFormFeedback`绑定被拒绝的值，修改后释放旧反馈，弹窗打开和关闭时重置。
3. 提交入口先收集全部既有错误，在明确的校验拒绝分支只调用一次 `src/utils/submitValidation.ts` 的 `rejectFormSubmission(本表单引用)`。可传原生Form引用、DOM引用，或公共 `AdminFormDialog` 暴露的 `getFormElement()`。不批量包装按钮，不拦截全局消息，不从星号或文案推断新规则。
4. 公共工具等待字段渲染后，按DOM显示顺序定位第一个错误，包含控件及下方提示；已完整可见时不滚动。滚动所在容器并避开固定导航，不改变焦点和字段值。分页、隐藏Tab或折叠内容需先通过页面现有导航API展示错误；使用 `reveal` 回调同步导航，不用模拟业务按钮或改CSS实现。
5. 图片、视频复用 `AdminMediaUpload` 的原有错误状态和tips；富文本错误放在原FormItem。动态规格、属性和价格使用原生控件tips或FormItem。原帮助文字保留，报错时优先具体错误，修正后恢复帮助。
6. API或网络失败走原catch反馈，不调用校验拒绝工具。输入和失焦校验不调用提交工具。新增模块同样接入并验证，不另建第二套规则。

## 错误提示承载（2026-10-19统一）

所有表单字段错误统一显示在控件外下方、左对齐，同一错误只显示一次，保留既有具体文案和错误状态。Textarea与其他控件遵守同一上层规则；字数统计位置另见[多行文本框专项规范](./textarea-standard.md)，不要求错误与统计同行。

复用已有TDesign错误来源：原生Form rules与FormItem管理的错误继续复用其规则和公开接口；已有独立错误状态的控件可使用官方status／tips。公共展示接入由实施方处理，不能为了移动提示删除校验、增加重复校验、只保留提交校验或改变原触发、清除和保存行为。不在FormItem和子控件重复显示同一错误，不要求用户决定内部接线。

## 提示空间与字段间距（2026-10-19统一）

- 提示空间只预留一次，纳入[通用表单间距](./form-style-standard.md)；不将Textarea空白tips、FormItem帮助行和正常字段间距重复叠加。无错误时已有帮助行或公共提示预留足够，不再额外添加空白提示行。
- 简短错误出现、消失时，控件高度及下方字段位置保持稳定。已有帮助文字与错误共用同一提示区域，报错时优先具体错误，清除后恢复原帮助说明，不新增“选填”等展示文案。
- 需要预留空间时，优先复用现有官方帮助行或公共布局。不能一律向所有Textarea增加不换行空格tips；只有确认没有其他占位且不增加总间距时，才可通过公开属性保留一次必要提示位。
- 长错误必须完整换行、可见且不遮挡下方内容，必要时允许布局自然增高；不能以保持绝对固定高度为由隐藏、裁切错误，或改成仅弹Toast。
- 手工FormItem、上传和带帮助字段复用现有公共form-feedback-layout.css的提示布局，不新增页面级错误定位CSS。Textarea的专项CSS授权只涉及统计位置及防遮挡留白，不扩大为重绘错误皮肤或另一套提示布局。

公共布局在普通表单末项无帮助文字的字段内按原生提示实际行高预留一次提示空间；报错前即存在，长提示正常增高。公共弹窗不再另外叠加表单底部占位，同样覆盖表单后紧接正文及嵌套表单的情况。已有帮助行继续复用；后续原生Space已提供间距时抵消末项占位，不重复增加空白。独立纯TDesign复现保留原始样式，用于区分原生行为与项目公共适配。

门店价格配置紧凑表格沿用用户批准例外：普通行57px，72px输入框垂直居中；错误仍在字段下方，仅报错行临时增加所需提示高度，修正后恢复。其他表单的布局稳定规则不变。

## 覆盖与验证

运营端、供应链端和门店端的普通弹窗、整页编辑、规格、动态价格表均执行统一反馈。成品现货封面、视频及原必填属性、大板品种等字段沿用各页现有要求；选填空字段不标红，不因首个媒体错误提前返回而漏掉其他字段提示。

源码守卫登记实际提交入口和公共反馈调用链。回归覆盖一次汇总、同时展示所有错误、首错定位、可见字段不多余滚动、输入和失焦安静、错误修正、合法提交及API和网络失败；适用完整前端回归零跳过、零重试。检查控件实际边框和具体文字，不以提示可见替代红框检查。

销售规格表价格控件：运营端、门店端和供应链端共用 `SpecPriceInput`。表格模式使用原有预留提示空间，抵消TDesign Table将tips设为普通文档流的默认规则；报错前后保持正常行高、输入框及同排按钮坐标，错误仍在控件下方完整显示。普通表单模式保持原布局。真实表格回归同时检查行高、各控件坐标、红框、提示边界和修正后恢复，不以独立控件夹具代替。

## 全局布局接入（2026-10-23）

公共 `form-feedback-layout.css` 统一承载原生规则、手工 FormItem、控件 tips 与上传反馈：短提示消耗既有一行空间，长提示进入正常布局并增高，不以绝对定位、隐藏或省略维持固定高度。带帮助字段与错误共用同一行；字体和行高保留原生组件样式，手工 FormItem 提示按原生22px行高补偿。现有普通字段间距保持，错误修正后恢复原布局。

动态规格紧凑网格通过商品共享样式预留一次提示行，保留单层两列、分层三列及按钮行为。价格控件复用原预留空间，紧凑系数表仅错误行按实际提示高度增高；不改变正常行高、输入框宽度和原校验规则。共享规则覆盖复用页面，不在各端复制错误定位样式。

回归必须同时证明短提示前后坐标稳定、长提示完整换行且不覆盖下一字段或底栏、末项可见、帮助恢复、重复名称修正及全部共享业务端；不能仅检查文字存在。

本次使用方复核包括：供应链成品现货/配件的单层与分层规格；三端商品及配件价格；两端大板；客户、订单原型及操作弹窗；商品基础数据、分类属性模板；员工邀请、账号权限、供应商、租户门店、门店级别与分类等原生表单。运营商品现有发布/编辑规格入口不可用，保持该只读边界，不为覆盖清单新增入口。上传同时核对表单内外换行；末项同时核对弹窗、嵌套表单与后续正文。
