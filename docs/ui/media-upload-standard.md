# 图片与视频上传全局标准

状态：2026-10-15 用户验收供应链成品现货后批准全局推广。现有及未来新增的独立图片／视频上传均遵守；只统一展示，不修改业务规则。

## 唯一公共入口

使用 `@/components/foundation` 导出的 `AdminMediaUpload`，内部直接使用 TDesign 原生 `t-upload theme="image"`。不复制上传卡片、页面皮肤或各端适配器；尺寸、背景、虚线边框、圆角、图标、悬浮操作及动效由原生组件提供，当前官方卡片110×110px。

多卡片使用原生 `t-space size="small" break-line align="start"`：small间距8px，自然换行，避免额外底部网格留白。每个位置最多一个文件，维持页面原有位置数和顺序。标题只在空卡片触发区显示，不重复展示外部标题、文件名、“点击上传”行或已被卡片数量表达的重复说明。

## 必须保留的业务约定

- 标题、允许文件类型、上传数量、必填条件、原有接口与权限由页面提供，不由组件推断或扩展。
- 成品现货保留五个固定主图位置，仅第一位置封面图必填，其余四个选填；删除封面不移动其他图片。视频沿用现有必填条件。
- 大板保留主图、扫描图、设计图必填和视频选填；运营编辑中的只读状态、供应链编辑能力不变。只读卡片可预览，但不可上传或删除。
- 工艺图片沿用现有表单校验；上传成功继续清除该字段错误。
- 提交校验失败时，仅缺失的必填上传位显示官方错误色边框与原有错误文案；上传成功后恢复。选填空位不标红。
- 使用显式 `errorMessage` 或原生FormItem错误状态反馈，公共CSS只补充Upload空卡片缺少的错误边框，不覆盖其他原生视觉。

## 视频、预览与生命周期

视频复用同一原生卡片。已有 `coverUrl` 时直接显示原封面，不生成替代封面；没有封面时仅本地读取视频首帧，限缩略图展示，不上传、持久化或替换原视频地址。首帧失败不得阻止原播放器预览和删除；更换、删除、卸载后清理读取资源，避免旧首帧回写新卡片。

点击已上传卡片或使用键盘继续打开页面原有图片／视频预览，不弹第二个原生图片查看器，不误开文件选择器。删除操作不触发预览。清空后恢复原生选择触发区。

组件只调用页面既有上传函数，成功后发出 `update:modelValue`、`uploaded`，删除／替换继续发出 `removed`。媒体ID、视频封面派生关系、待释放集合、保存／取消、引用绑定与资源释放仍由原业务处理；失败不提交新值、不释放旧值、不伪装为成功。

## 已推广范围与排除项

- 供应链成品现货的独立商品主图、商品视频上传；运营端复用同一表单代码，保留当前编辑媒体只读及无发布权限的事实，不开放新入口。
- 供应链大板的独立主图、扫描图、设计图、视频上传，以及运营大板同入口的只读媒体预览；运营端当前不开放发布入口。
- 运营工艺管理的工艺图片上传。
- 富文本 `ProductRichEditor` 与客户跟进通用附件 `AdminOfficialMediaUpload` 本次不动。门店成品现货无独立上传入口，门店无大板管理，不新增入口。

## 后续实施与验证

新增模块直接复用公共入口，仅传入既有业务参数和回调。禁止再建端专用组件、自绘皮肤或复制尺寸／留白。源码守卫检查唯一入口、原生主题和排除边界；回归验证上传成功／失败、替换与删除释放、封面位置、必填恢复、只读、预览以及原有表单保存／取消。
