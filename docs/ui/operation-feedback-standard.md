# 操作校验与反馈全局标准

确认日期：2026-11-05。适用于运营端、供应链端、门店端现有及未来模块。

## 边界

仅前移已有执行条件并统一反馈，不新增业务限制，不修改权限、数据范围、状态、价格库存或批量执行策略。只读预检不能产生目标业务变更；实际提交仍以服务端最终校验为准。销售订单当前仅为模拟原型。

## 操作类型与流程

| 显式类型      | 处理规则                                                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| single        | 点击后先检查已有条件。不满足立即警告 Toast；满足才进入原有确认和执行流程                                                                                   |
| batch-partial | 只检查勾选和处理中等整体前提；按原确认逐项执行，允许部分成功，最终用结果弹框汇总成功数量、失败对象及原因。不得强制逐项预检全部通过，不得由一个失败阻断整批 |
| batch-atomic  | 保留既有整体校验和原子性，不改为部分成功、不新增整体阻断条件                                                                                               |
| form          | 正常进入填写界面；提交时按字段校验标准反馈，不以尚未填写阻止打开表单                                                                                       |
| view / query  | 查看、查询、取消等非执行入口按原行为保留                                                                                                                   |
| dispatch      | 混合入口必须登记每个分支的真实类型，不从按钮文案猜测                                                                                                       |

禁用和显隐规则保留；预检通过不省略原风险确认，原来无需确认的动作不统一增加确认。

## 提示形式和话术

业务条件阻断使用公共 `adminFeedback.warning` 的 Toast，自动消失，无需点击关闭。检查异常或执行失败使用错误 Toast；成功复用公共成功反馈。禁止使用“我知道了”的无法操作确认框。保留风险确认、表单、详情及批量结果弹框；批量最终汇总不属于反馈滞后。

话术使用具体原因和确实可执行的处理建议；缺信息优先“请先……后再……”。正式对象名称不得混用。能同时可靠确定的关联缺失项尽量一次告知，不连续弹多条；没有已知处理路径只说明原因，不编造建议。内部 SQL 和堆栈不直接展示。

| 场景           | 标准话术                                         |
| -------------- | ------------------------------------------------ |
| 缺门店分类     | 请先选择门店分类后再上架                         |
| 缺商品售价     | 请先完善商品售价后再上架                         |
| 两者都缺失     | 请先选择门店分类并完善商品售价后再上架           |
| 有下级分类     | 该分类包含下级分类，请先删除或转移下级分类       |
| 分类关联商品   | 该分类已关联商品，不能删除，请先停用该分类       |
| 价格配置被使用 | 该价格配置正在被商品价格使用，不能删除，请先停用 |
| 所属租户归档   | 所属租户已归档，请先恢复租户运营                 |
| 检查异常       | 操作条件检查失败，请稍后重试                     |

沿用公共 Toast 的主题、时长、位置及去重机制，不自绘皮肤。表单字段红框、具体提示、汇总 Toast 和首错定位遵守表单校验标准，不用操作 Toast 替代。

## 实现与异步保护

复用执行所用的业务校验，不能单独维护一套失配的前端条件。必要服务端预检继承对应执行动作的身份、功能及数据作用域，不接受客户端覆盖组织参数。

公共入口 `useOperationPreflight` 负责检查期间防重复、组件销毁和身份／路径变化后的过期响应保护、业务拒绝与请求异常的反馈。模块提供真实检查；公共 execute 负责同一操作实例的执行串行保护，并以原生 loading 反馈。不能把空检查或源码检查通过视为业务正确。预检结果不得代替提交时校验。执行期间沿用处理中保护。

## 覆盖与准入

操作台账为 `operation-feedback-registry.json`，页面／共享页面的绑定、脚本指纹、明确类型和分支均登记；路由别名由 `operation-feedback-audit.md` 标明。新增页面、新操作或脚本变化必须审查真实调用链和既有条件、更新精确登记及对应测试。保留原始视觉基准，业务变更使用获批精确补丁登记。

公共门禁 `test:source-guards` 通过现有反馈守卫调用 `operation-feedback-policy.mjs`，拒绝漏登记、实现指纹漂移、阻断弹框和将部分成功批量设置成逐项预检。反例证明守卫会拒绝错误。公共运行单测覆盖业务阻断、网络异常、重复点击和过期响应；业务/API测试证明具体条件和隔离。源码守卫不能证明所有业务含义正确，也不等于独立不可绕过的安全机制。

新增模块必须显式登记操作类型，复用公共反馈及适用预检，并提供业务验证。不能仅复制旧页面作为合规依据。

## 验收与例外

逐项核对：不满足条件首次点击 Toast；满足条件原确认正常；异常不放行；重复点击及响应乱序不串对象；确认期间变化由后端拒绝；批量混合结果不改变策略且准确汇总；表单及权限范围保持原行为。

每项有迁移、已符合或不适用依据及验证证据才可关闭。未知或失败项明确保留，不宣称全系统完成。特殊例外须用户批准对象、原因和范围；历史实现不自动成为例外。规范、代码、守卫、测试、台账及剩余风险共同构成交付物；合并、运行交接和生产发布按独立授权处理。

批量保留边界：不得将既有串行遇错停止改为并发或继续执行，不清空原本需要保留的失败／未执行选择，不为统一提示擅自替换既有批量流程。原有批量上架／删除的部分成功及结果弹框保持不变；其他已登记批量按真实策略保留。
