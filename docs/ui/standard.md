### 描边按钮与禁用状态（2026-10-19确认）

适用于各业务端采用描边形式的按钮，包括附件上传、批量设置及后续同类入口。

- 使用 TDesign 官方 `variant="outline"`，主题继续由既有 `buttonTheme`／`buttonFunctionFor` 功能映射提供；保留当前按钮主题，不为调整禁用外观更换主题。
- 禁用通过官方 `disabled` 属性表达，直接保留对应主题的官方文字、图标、边框、背景及交互状态；不手写禁用样式。
- 禁止通过页面 CSS、深度选择器、全局覆盖、内联样式或主题变量单独改写禁用颜色、透明度、边框和背景；不引用 `.t-is-disabled` 等内部类重绘禁用态，也不以仅变淡外观或拦截点击代替真实禁用。
- 不因禁用外观擅自将既有描边按钮改为实心、文字、虚线或其他形式。当前官方没有为同一主题提供另一套描边禁用外观选项，不能将自定义皮肤称为官方样式。
- 保留现有禁用表达式、加载状态、权限显隐、按钮图标与文案、事件及业务交互。本次规则登记不授权修改运行代码或业务条件。

### 确认、取消与校验

- 确认按钮跟随实际动作：如归档／停用／下架为warning，启用／恢复为success，删除为danger。即使按钮文案是“提交”，也按实际动作取色。无操作可执行的阻断弹窗“我知道了”归入close，使用default。
- 取消始终default；关闭、返回亦为default。取消按钮的null（隐藏）、禁用、加载、回调及文案不变。
- 校验失败使用字段红框、字段下方具体提示和原有统一提交反馈；创建规格、选择选项等正常动作不因错误改为danger。校验规则、提交时机和定位行为不变。
- 删除与彻底删除同为danger，以原名称、说明和确认流程表达后果差异，不另造深红色。清空权限选择归入clear-selection，不按“清空”二字推断危险色。

4. 同步文档、公共实现的消费者及相关测试。新按钮漏登记、登记无依据、未知标识、页面直接选色或确认漏接入，必须修复后才能通过门禁。

### 控件边界与门禁

选中态导航、业务类型选择、价格跟随模式控件及图片／视频缩略预览面不等同于普通动作按钮，保留内容和状态表达，不强制涂成动作色。当前准确入口登记在 `button-controls.json`，记录文件、结构指纹、类型及保留理由；新增或变化必须单独审查，不接受仅加标记绕过。TDesign原生内置分页、富文本工具与媒体查看器内部工具沿用组件，不逐个重写。独立上传的上传按钮通过公共上传入口引用upload主题；上传状态及生命周期不变。

`button-color-policy.mjs` 接入既有 `test:source-guards` / `check:ui-templates`，全量扫描src，新增页面自动纳入；类型检查与功能回归同时保留。公共列表和弹窗的功能标识均为必填；没有按文案猜色、默认蓝色或旧颜色兜底路径。旧动作模型不再保存重复theme字段，唯一颜色来源是登记表。

## 静态检查零告警

ESLint 全量、增量、自动修复和提交前检查统一使用 `--max-warnings=0`；现有 CI 通过 `quality:static` 执行同一门禁。任何剩余告警均使检查失败，不关闭规则或放宽告警阈值。可选属性应明确默认值；未传入本身有含义时保留 `undefined`，不为消除告警改变空值、取值优先级或业务行为。测试替身按真实接口声明属性类型，无用绑定仅在保持调用及行为后清理。

## 执行按钮命名（2026-10-16确认）

这是基于TDesign原生组件的项目命名约定，不是官方强制文案。覆盖各端新增、编辑表单（弹框、整页和抽屉）及业务操作确认弹框。新增使用“确认新增”，编辑使用“确认保存”；业务操作使用“确认＋完整操作名称”，批量保留“批量”，例如“确认停用”“确认批量停用”“确认下架”“确认批量下架”。保留入口、标题、字段、默认值、校验、请求、权限、数据范围、加载、禁用、事件及关闭流程。

公共实现为 `src/components/foundation/actions/confirmation.ts`。表单显式使用 `formConfirmation('create' | 'edit')`，随真实模式切换；独立保存按钮使用 `formConfirmationText`。业务操作使用 `operationConfirmation(登记动作, 是否批量)`；完整名称及明确兼容别名登记在现有 `button-functions.json` 的 `confirmationActions`。不按标题、旧按钮文案或选中数量推断动作和批量状态；恢复类需明确登记“取消归档”“放回仓库”“恢复运营”等实际含义。

`AdminDialog` 和 `AdminFormDialog` 的 `confirmation` 必填；`AdminConfirmDialog` 使用已登记 `action` 和显式批量状态；原生弹框通过 `dialogButtonProps` 生成。确认按钮仅提供加载、禁用等行为选项，不覆盖名称或主题；原有功能映射继续决定颜色。取消保留“取消”；详情关闭、无法操作的“我知道了”、无执行按钮及下一步导航显式登记，保留其原有含义。

新动作先登记完整名称，再接入公共入口；未知动作和表单模式不得回退为“提交”“确定”。现有源码守卫覆盖存量与新增页面：缺失配置、未登记动作、手写确认文案或绕过公共入口均失败；运行时同样拒绝未知动作。特殊场景须明确登记用途及固定文案，并补对应检查，不能自行豁免。

## 顶部身份展示（2026-10-16确认）

顶部当前身份和 Select 切换选项均使用两行信息：名称在上，身份类型在下；不再使用“合”等小标签，也不缩小官方字号。名称使用官方正文14px，类型使用官方辅助文字12px；按现有 `clientCode`、门店及 `storeType` 展示运营端、供应链端、门店端及合伙人门店／大板供应商／成品供应商／工厂，缺失类型只展示已知业务端，不按名称猜测。选项保留原生选中态，并为当前登录身份显示勾选。

保留品牌、用户资料、可切换身份范围与顺序，以及原有切换接口、会话保存、跳转、失败恢复和全部权限逻辑。顶部使用原生无边框 Select 和身份图标，与品牌紧凑排列；保留官方悬停与焦点反馈。两行选项的高度、内边距及内容宽度仅在专属 `.zdm-identity-popup` 浮层内适配，避免组件重建导致作用域样式失效；勾选靠右，保留原生浮层定位、键盘操作与选择行为，视觉按已确认方案C还原。

方案C（2026-10-16确认）：品牌与当前身份之间用细分隔线；入口使用浅蓝底身份图标和两行文字，下拉使用中性图标、两行信息、浅蓝选中态及右侧勾选，并显示“切换身份”标题。平台／门店交界使用分隔线，保留原有候选顺序；图标仅由既有身份字段决定，不影响权限和切换。单一身份使用同样的信息布局，不显示切换控件。字体与间距复用官方变量；明确确认的配色、图形与投影按效果图局部还原并精确登记。

还原方案C的上述局部色值以 `visual-refactor.json.approvedVisualDeclarations` 精确登记文件、选择器、属性、值及用户授权依据。守卫只允许完全匹配的声明，并拒绝未使用的登记；其他组件与新声明仍须使用官方语义变量，不得扩大此局部授权。

身份切换收尾对照（2026-10-16）：顶部图标容器32px、列表图标容器40px；鼠标点击入口不显示表单蓝框，键盘聚焦仍保留可见焦点。切换过程仅在名称旁保留一个加载反馈并阻止重复请求，成功后持续到新文档接管；成功后直接替换到原有dashboard入口，保留完整文档初始化和原路由权限重定向，避免先SPA跳转再刷新造成的中间帧与重复加载。失败时仍保留原会话、权限和当前身份，允许重试。

用户已确认的视觉效果图优先于该区域的官方默认外观；有差异时只在准确授权区域还原，并登记精确视觉声明与回归检查，不能扩展为全局主题替换。

## 文字链接悬停统一规则（2026-10-19确认）

全平台业务文字链接统一显式使用 TDesign 原生 `hover="color"`，悬停只变色，不显示下划线；适用于列表操作、可点击名称、详情操作、附件及日志等文字链接入口。新页面和现有页面均遵守，不依赖 Link 默认的 `hover="underline"`，不通过 CSS 覆盖组件悬停效果，不设置强制下划线。保留原有 theme、尺寸、间距、位置、图标、权限、禁用条件、键盘操作与点击事件，以及已经确认的逐记录悬停显隐。普通按钮及商品富文本正文的下划线格式不属于此文字链接规则。

`check:ui-templates` 和 `test:source-guards` 检查 src 内全部业务 Vue 模板；缺失或使用其他 hover 配置、强制显示下划线均失败。官方上游原始快照保持只读。
