# 数值类型控件输入规范

状态：2026-11-02用户确认。本文件承接原《表单、批量填写与上传外观全局标准》中的“数字精度分类”条款，并补齐数值输入交互。最新确认口径为：全系统默认不允许负值、允许零值；需要负值时，由用户提出具体业务需求并批准字段例外；小数默认最多两位，不足补齐。本文是数值专属规则的唯一维护入口。

本轮仅沉淀、迁移规范，不修改控件、页面、前后端校验、数据库、权限、测试或CI。规范生效不代表存量实现已迁移；已有实现与新规则的差异须在后续获准范围内处理，不以现有代码自动认定专项例外。

## 适用范围与引用层级

适用于所有现有及后续业务端，包括运营、供应链和门店的表单、列表行内编辑、弹窗、抽屉、批量填写及数值范围查询。业务数值包括价格、金额、库存、数量、系数、尺寸和模板中明确配置为数值的属性。

手机号、验证码、ID、编号等标识不属于业务数值，不转换成整数或小数，不补小数位。数值选项的选择控件不因选项内容为数字而变为数值输入框；只读展示和自动计算结果不新增输入校验。

统一使用一套规则，其中区分整数模式和小数模式，不维护两份重复规范。

| 规则归属                                     | 本文处理方式                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 标签、控件宽度、表单类型、字段及提示空间预算 | 引用[表单样式规范](./form-style-standard.md)，不重复定义                                          |
| 字体、颜色及原生控件状态外观                 | 引用[全局字体标准](./typography-standard.md)及[全局UI规范](./standard.md)，不增加另一套皮肤       |
| 占位文案                                     | 引用[全局占位文案标准](./placeholder-standard.md)                                                 |
| 错误承载、标红、汇总反馈及首错定位           | 引用[全局表单校验反馈标准](./form-validation-standard.md)，本文只补充数值特有的触发条件和具体文案 |
| 数值输入过程、模式、精度及规范化             | 由本文唯一维护，其他文档只引用                                                                    |

## 模式、默认值与字段配置

| 配置项         | 默认规则及例外要求                                                 |
| -------------- | ------------------------------------------------------------------ |
| 模式           | 明确选择整数或小数，不在实现中根据字段名称猜测                     |
| 整数精度       | 零位小数，不接受小数点，不补`.00`                                  |
| 小数精度       | 默认最多两位；合法非空值不足两位时，在失焦或确认时补齐两位         |
| 负值           | 全系统默认不允许；只有用户明确批准允许负值的具体字段才能例外       |
| 零值           | 全系统默认允许；只有用户明确要求禁止的具体字段才能例外             |
| 必填           | 按字段已确认要求明确能否留空，不由统一控件新增必填条件             |
| 最小值、最大值 | 默认不额外附加；确有明确要求时登记具体上下限及包含关系             |
| 增减步长       | 使用增减操作的字段明确步长；不因统一控件擅自改动既有步长或键盘行为 |

原已确认的默认分类约定迁入本文件：库存、数量采用整数；价格、金额、系数及模板数值属性采用小数。明确批准的专项例外按登记执行。这是字段配置的默认分类依据，不授权按名称自动识别、改写现有字段。

精度、正负、零值、必填及范围分别管理。负值按默认不允许执行；不能因为某字段是库存、成本价或金额就自行附加“必须大于0”等其他限制。需要例外时记录具体字段、所在业务端及入口、限制、用户确认依据和适用范围；特殊精度同样登记。不得以底层组件默认行为或存量实现代替用户要求。

## 输入过程

| 场景           | 规则                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 数字字符       | 接受半角`0～9`                                                                       |
| 小数点         | 整数模式不接受；小数模式最多一个，采用`.`，主键盘与小键盘小数点操作一致              |
| 负号           | 默认不接受负号；只有明确批准允许负值的字段才接受一个位于最前面的`-`                  |
| 非法字符       | 字母、汉字、表情、内部空格等不接受本次输入，保留原内容，不静默过滤后拼成另一个数值   |
| 其他数值写法   | 正号、科学计数法、十六进制、千分位逗号、百分号默认不接受；专项需求另行确认           |
| 删除与编辑     | 支持退格、删除、清空、选中替换和光标中间编辑，不强制跳到末尾、不因补零重置光标       |
| 输入过程中补零 | 不补，避免打断连续输入                                                               |
| 精度超限       | 默认最多允许输入两位小数，超过精度的本次编辑不接受，保留编辑前内容；不截断或四舍五入 |
| 中文输入法     | 不打断组合输入，组合结束后按最终替换内容处理                                         |
| 单位           | 作为控件附加信息展示，不混入提交数值                                                 |
| 禁用、只读     | 保留原生交互和样式，不产生修改或新增输入校验                                         |

判断一次编辑是否合法时，使用光标选区替换后的完整内容，不仅判断最后追加的字符。输入期间不新增Toast或滚动，不新增回车提交、ESC关闭或滚轮改值行为，保留所属表单的既有处理。

## 输入中间状态

| 模式                   | 输入期间暂时允许    |
| ---------------------- | ------------------- |
| 整数且明确批准允许负值 | 单独的`-`           |
| 小数                   | `.`、`12.`等        |
| 小数且明确批准允许负值 | `-`、`-.`、`-12.`等 |

负号相关中间状态仅适用于明确批准允许负值的字段；默认字段不接受负号。合法中间状态在连续输入时不提前报格式错误。失焦或确认时必须能够形成有效数字：`12.`可以规范化为`12.00`；`.5`、`-.5`分别规范化为`0.50`、`-0.50`。单独的`-`、`.`、`-.`不是空值，即使字段选填，也应在失焦或提交时提示输入有效数字，不能静默转换成0或清空。

## 零值、前导零与规范化

默认允许零值，不采用“禁止首位输入0”来实现零值限制，以免阻断`0.5`等合法输入。开头为`0`或允许负值字段中的`-0`时，不接受紧接着的第二个`0`；允许继续输入小数点，例如`0.5`、`-0.5`。按选区替换后的完整内容判断，连续前导零的整次编辑或粘贴不应用，不静默删零后接受。其他合法输入中的多余前导零仍在失焦或确认时规范化。

| 输入          | 整数模式规范化结果           | 默认小数模式规范化结果     |
| ------------- | ---------------------------- | -------------------------- |
| `0`           | `0`                          | `0.00`                     |
| `012`         | `12`                         | `12.00`                    |
| `00`、`00.50` | 不接受本次编辑，保留原内容   | 不接受本次编辑，保留原内容 |
| `-0`          | `0`                          | `0.00`                     |
| `-0.00`       | 不适用，整数模式不接受小数点 | `0.00`                     |
| `-00`         | 不接受本次编辑，保留原内容   | 不接受本次编辑，保留原内容 |

表中含负号的示例仅适用于明确批准允许负值的字段，默认字段不接受这些输入。上述规范化只处理合法数值的表示形式，不改变其数值含义。字段有明确零值禁用要求时，保留输入并提示，不擅自改成其他数字。

## 小数精度与补零

默认小数最多两位、不足补齐两位；整数不补小数。输入中不补，合法非空值在失焦或确认时补齐。特殊精度只有经用户明确确认并登记具体范围后执行。

| 输入     | 默认两位小数的处理                                       |
| -------- | -------------------------------------------------------- |
| `12`     | 失焦或确认时为`12.00`                                    |
| `12.5`   | 失焦或确认时为`12.50`                                    |
| `12.34`  | 保持`12.34`                                              |
| `-12.5`  | 仅明确批准允许负值的字段，失焦或确认时为`-12.50`         |
| `12.345` | 不接受本次编辑，保留编辑前内容，不转换成`12.34`或`12.35` |

规范化前先判断输入是否符合模式和精度，不能先四舍五入或截位再校验。不得因浮点转换丢失有效数字、溢出或自动改成科学计数法。后续控件与接口改造需保证数值往返一致；存储能力无法容纳时明确拒绝，不静默改值。

## 粘贴规则

粘贴与键盘编辑使用相同的模式及校验要求，并校验替换后的完整内容。

- 可以去除粘贴内容首尾空白；内部空格仍为非法字符。
- 含非法字符、重复小数点或不合法负号时，整次粘贴不应用，原内容和选区编辑能力保留。
- 不把`12a3`过滤成`123`，不把带单位、逗号或百分号的内容擅自转换成数值。
- 整数模式粘贴`12.5`或`12.00`，整次不应用。
- 小数模式粘贴`12.345`，整次粘贴不应用，保留原内容，不截位。连续前导零的粘贴同样整次不应用。
- 粘贴不能绕过负值、零值、精度或明确的范围限制。限制与具体反馈沿用同一次完整内容校验。

## 数值校验时机与文案

| 内容                         | 默认触发时机                                                 |
| ---------------------------- | ------------------------------------------------------------ |
| 不可能合法的字符组合         | 阻止本次输入；不弹Toast，不修改为另一个数值                  |
| 小数位数超限                 | 正常编辑时阻止超限输入；已有值或外部传入的超限值显示字段错误 |
| 不完整的中间状态             | 失焦或提交时提示                                             |
| 必填、明确的零值限制及上下限 | 失焦或提交时提示；初始空框不直接报错                         |
| 已显示错误的字段             | 修改后即时重新判断，合法即清除                               |

非法输入必须阻止提交。选填空值不转换成0，不作为非法中间状态。必填字段在已触发校验后清空时，按必填要求显示错误；不能通过清空绕过校验。

| 数值错误                       | 具体文案                                          |
| ------------------------------ | ------------------------------------------------- |
| 整数格式错误                   | 请输入整数                                        |
| 小数格式错误或无法形成有效数字 | 请输入数字                                        |
| 精度超限                       | 最多输入N位小数，默认N为2                         |
| 默认不允许负值的字段           | 请输入大于或等于0的数字                           |
| 已明确禁止零值的字段           | 请输入非零数字                                    |
| 明确的最小值                   | 请输入大于或等于X的数字；不含边界时按实际要求表述 |
| 明确的最大值                   | 请输入小于或等于X的数字；不含边界时按实际要求表述 |

默认不允许负值，正常输入与粘贴均不接受负号；校验已有值或其他入口传入的负值时，使用对应的非负错误提示。明确批准允许负值的字段不因负值报错；默认不因零值报错。其他范围类错误仅在存在对应的明确字段限制时产生。有多项错误时，字段只展示一条当前可修正的具体错误，先处理格式、再处理精度、最后处理范围，修正后更新。必填文案引用占位和校验反馈标准，不在此复制公共句式。错误位置、字体、布局、汇总提示及定位均由公共校验反馈标准维护，不重复接入导致同一错误显示两次。

## 批量填写、历史值与前后端一致性

- 批量填写留空表示不覆盖，不能将空值自动转为0；默认允许的0属于已填写数值，应按合法值处理；负数只有在字段已明确批准允许负值时才按合法值处理。
- 所有已填写字段校验通过后统一应用，不允许部分覆盖；校验失败保留输入、选择范围和原数据。
- 已确认的商品绑定版本兼容规则继续在原适用范围执行：历史值未修改时原样保留，不因补零被视为用户修改或静默回写；实际修改值及新增SKU按绑定版本和相应精度规则校验。
- 上述历史兼容不扩散为全系统历史值一律免校验。其他字段的历史异常值处理须明确，不静默截断、清空或猜测修复。
- 前后端应采用一致的模式、精度和明确业务限制，前端不能替代后端校验。规范更新本身不授权修改接口、存储或既有数据。

## 后续实现与验证边界

后续获准实施时统一复用公共数值输入能力，由字段声明模式和必要的例外配置，不在业务页面分别复制输入正则、补零及错误文案。保留原生组件外观及已有业务事件；不因统一数值交互擅自修改其他字段、权限、API、保存或取消流程。

存量迁移须结合已扫描字段清单逐项明确范围和例外，另行获得实施授权。本轮不修改公共控件、业务页面、后端、数据库、测试、守卫、CI或依赖，不运行全系统控件迁移，不宣称已有自动化守卫覆盖本文全部新要求。
