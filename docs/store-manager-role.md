# 门店内置店长：实现与验证边界

依据：2026-10-16本任务用户确认。适用于现有门店及运营管理平台后续创建的门店；角色属于各自门店，不是运营平台角色。

- 固定语义标识为`roles.builtin_key=STORE_MANAGER`，显示名称为“店长”。每个门店独立ID；原有`code`继续保留，后续业务不能通过可编辑名称或固定数字ID识别店长。登录和会话返回原角色编码，同时补充内置语义标识；它不等于功能授权。
- 门店创建与店长创建在同一事务完成。新建角色启用、功能权限为空，不自动分配给任何员工。现有同名门店角色原地标记为内置，保留ID、原编码、备注、功能授权、人员关联、价格规则引用；没有店长的已有门店补建空权限角色。
- 基本资料不可编辑，角色不可停用、不可删除、不可重复。数据库按端和组织约束内置键唯一，同时约束其名称、状态和归属；角色接口拒绝伪造内置标记、保留编码及重命名为店长。门店彻底删除的既有组织清理不受单角色不可删除规则影响。
- 独立“权限”入口保留，具备相应权限的管理员可首次配置及后续调整；不增加默认功能授权，也不绕过终端已开放功能范围。店长不受任职人数限制，管理员按既有员工角色分配流程配置。
- 内置角色作为组织级系统资源，在本组织合法数据范围内可见，不因创建人为其他人而消失；普通角色保持既有创建人数据范围。没有功能授权或未配置数据权限仍不可操作，其他端、租户和门店不可访问或绑定。
- 门店管理员以有效身份为准拥有本店全部数据操作能力；店长必须同时具备功能与数据授权。全部数据范围可以维护全店客户，本人范围只维护本人；普通员工保留原有业务约束。

验证覆盖原地迁移保留人员和权限、价格规则引用、补齐旧门店、新门店原子创建、重复和停用约束、前后端入口保护、仅权限授权可配置、多人任职、跨组织绑定隔离及客户操作的功能／数据双门禁。当前任务数据库迁移前已备份；本说明不授权其他环境的数据清理，也未修改Notion。
