# 装点猫轻量平台架构约束

## 目标

当前阶段先实现可操作系统，不做微服务拆分。后端按平台业务中心组织，让管理后台、设计师端、C 端、门店端、工厂端、安装端、供应商端未来都能复用同一套平台能力。

## 分层约束

- 生态入口层：前端页面、小程序、移动端，只处理展示、交互和端侧 DTO。
- API 接入层：按端划分路径，例如 `/api/admin/**`、`/api/designer/**`、`/api/customer/**`。
- 平台业务层：账号权限、商品中心、库存中心、订单中心、结算中心、工艺中心、消息中心等。
- 数据资产层：所有业务数据通过后端服务落库，禁止前端或端侧系统直连数据库。

## 当前模块边界

- `auth`：登录、统一身份入口。
- `tenant`、`store`、`role`、`employee`：系统管理中心。
- `catalog`：商品中心，负责分类、属性、属性值、基础资料。
- `inventory`：库存中心，负责大板品种、大板库存、成品库存。
- `supplier`：供应商协同，负责供应商档案。
- `craft`：工艺中心，负责工艺基础资料。
- `order`：订单中心，负责统一订单最小模型。

## 演进规则

- 新功能先进入对应业务中心，不写成某个端专属逻辑。
- Controller 可以按端拆分，Service 优先复用平台业务能力。
- 新增表必须通过 Flyway 迁移。
- 管理后台页面逐步从内存数据迁移到 API，不在同一轮强行替换所有页面。
- 订单中心后续必须引入状态机，再扩展销售单、生产单、安装单、售后单和履约节点。
- 库存中心后续必须支持锁库、预留、释放、调拨、盘点、损耗和批次/唯一码追溯。
- 结算中心后续独立建模，不把分润、对账、支付状态散落在订单表里。
