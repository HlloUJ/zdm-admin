# 装点猫轻量平台架构约束

本文只描述技术分层和实现边界。产品定位、模块职责和业务语义以 Notion 中状态为“有效”的产品架构、分层说明及专项原则为准。现阶段最终图及权威文档入口见 [产品架构总览](product-architecture.md)。

## 目标

当前阶段先实现可操作系统，不做微服务拆分。后端按平台业务中心组织，让管理后台、设计师端、C 端、门店端、工厂端、安装端、供应商端未来都能复用同一套平台能力。

## 物理部署边界

- 当前采用“共享平台后端 + 模块化单体”：所有端共用一个后端应用和统一数据模型，不为每个前端复制后端。
- 不同端通过独立 API 路径、身份和权限隔离；共用业务规则下沉到对应业务模块。
- 现阶段不拆微服务。只有当模块具有独立扩缩容、故障隔离或独立交付的真实需求时，才评估服务拆分。
- `accounts`、`account_identities`、角色、权限、会话和审计属于平台共享安全能力，不归某个业务端私有。

## 与产品架构的对应

- 产品架构保持“生态入口层、业务应用层、智能中台层、数据资产层”四层；下文 API 接入层等是工程实现分层，不构成新增产品层级。
- 业务应用层包含设计协同、门店赋能、供应链协同、生产 MES、履约、财务六个核心系统，以及城市合伙人、设计师社区、客户服务、售后、系统管理中心五个辅助系统。
- 系统管理中心承担平台经营与运营规则；供应链协同承担货源、采购与供货及相关生产组织。管理后台是统一内部操作入口，页面所在入口不决定领域职责。
- 业务系统的领域边界不直接对应独立进程、独立前端或独立数据库；继续使用共享后端和模块化单体，复用商品、库存、订单、工艺、结算等公共能力。

## 分层约束

- 生态入口层：前端页面、小程序、移动端，只处理展示、交互和端侧 DTO。
- API 接入层：按端划分路径，例如 `/api/admin/**`、`/api/designer/**`、`/api/customer/**`。
- 平台业务层：账号权限、商品中心、库存中心、订单中心、结算中心、工艺中心、消息中心等。
- 数据资产层：业务支撑中台是唯一的数据操作入口；所有业务系统必须通过中台 API 操作数据，禁止前端、端侧系统或业务系统绕开中台契约直接访问数据库。
- 中台 API 是统一公开契约，在模块化单体中可由同一后端的服务接口承载；数据访问实现封装在对应中台能力内部，不因产品系统分层而强制引入微服务或内部 HTTP 调用。

## 当前模块边界

- `auth`：登录、统一身份入口。
- `tenant`、`store`、`role`、`employee`：系统管理中心。
- `catalog`：商品中心，负责分类、属性、属性值、基础资料。
- `inventory`：库存中心，负责大板品种、大板库存、成品库存。
- `supplier`：供应商档案基础模块，为供应链协同提供供应商资料；现有档案能力不等同于完整的采购、供货与生产协同系统。
- `craft`：工艺中心，负责工艺基础资料。
- `order`：订单中心，负责统一订单最小模型。
- `security`：当前身份、服务端会话、功能权限、数据权限和安全审计。
- `common`、`config`：跨模块技术基座，不承载具体业务规则。

## 架构确认与实现调整

- v23 确认的是产品系统职责与协同关系；本次文档同步不执行既有页面、API、数据库或权限迁移。
- 后续调整供应商、大板、成品现货等功能前，依据 [架构协同关系与供货场景](https://app.notion.com/p/3dc572fed032819aa21ee1a095e9018f) 和有效专项规则确认具体归属及迁移方案，不从架构图横向排列推导订单必经路径。
- 架构图与模块清单不作为功能已实现或已通过验收的证据，实际实现状态仍以当前代码和对应验证为准。

## 演进规则

- 新功能先进入对应业务中心，不写成某个端专属逻辑。
- Controller 可以按端拆分，Service 优先复用平台业务能力。
- 业务模块不得直接引用其他业务模块的内部类；跨模块协作应先定义明确的公共契约。
- `PlatformModuleBoundaryTest` 自动检查业务模块的直接依赖边界。
- 管理端写操作必须记录安全审计；权限判断必须以后端当前身份为准，不能只依赖前端按钮显隐。
- 新增表必须通过 Flyway 迁移。
- 管理后台页面逐步从内存数据迁移到 API，不在同一轮强行替换所有页面。
- 订单中心后续必须引入状态机，再扩展销售单、生产单、安装单、售后单和履约节点。
- 库存中心后续必须支持锁库、预留、释放、调拨、盘点、损耗和批次/唯一码追溯。
- 结算中心后续独立建模，不把分润、对账、支付状态散落在订单表里。
