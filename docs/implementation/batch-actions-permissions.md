# 批量操作与权限合并实施边界

本批次在已有入库途径、运营日志及大板标题调整提交之上串行实施，保留原提交。以下三项由用户确认实施，不包含正式推送、合并或生产发布。

## 一、批量上架

现有8页（供应链/运营成品现货、配件、大板；门店成品现货、配件）的全部与仓库中入口统一后台逐件处理、独立事务、失败继续、批次结果弹窗。价格、库存、资料、来源校验、日志和上下游联动沿用既有业务。

## 二、批量删除

上述8页的全部、仓库中、已上架新增批量删除；仅确认，不填写原因及说明。正常商品进入本端回收站，不替代彻底删除，不先下架。每件和联动独立事务，失败继续；返回完整统计和按原因分组的失败商品ID，门店使用页面商品ID。

完整响应后清空本次选择、刷新列表/数量/分页。请求结果未知不自动重试、不报告整批失败；刷新异常不修改已取得的执行结果。选择范围及跨页规则保持原样。

## 三、权限合并及旧授权映射

同端、同模块、同状态内，单条与批量共用上架、下架、放回仓库、彻底删除、删除；客户管理共用归档、取消归档、彻底删除。客户执行逻辑不变。清空回收站、客户批量调整归属、价格配置、查看/详情保持原边界，不新增门店大板。用户追加确认仅将价格系数的权限显示名称从“批量设置”改为“设置价格系数”；页面按钮、编码和业务不变。

| 旧编码后缀                                     | 统一编码后缀         |
| ---------------------------------------------- | -------------------- |
| 商品 `.batch-shelf` / `.warehouse.batch-shelf` | `.warehouse.shelf`   |
| 商品 `.selling.batch-off-shelf`                | `.selling.off-shelf` |
| 商品 `.recycle.batch-restore`                  | `.recycle.restore`   |
| 商品 `.recycle.batch-purge`                    | `.recycle.purge`     |
| 客户 `.daily.batch-archive`                    | `.daily.archive`     |
| 客户 `.archived.batch-restore`                 | `.archived.restore`  |
| 客户 `.archived.batch-purge`                   | `.archived.purge`    |

旧单条与批量授权归入同一业务动作，按确认方案同时具备单/批能力；不产生其他状态、模块、业务端的操作授权。沿用现有操作隐含所属状态查看的归一化规则。终端和角色分别归一化后再取交集；已有配置读取时生效，下一次保存写入统一编码，不直接批量改写持久权限CSV或增加Flyway迁移。旧CSV保留可追溯，不因目录去重丢失既有授权。

全部Tab的单条按钮按每条当前状态授权；批量删除须同时有仓库中和已上架删除授权，各状态Tab只需本状态授权。上架只涉及仓库中。实际执行仍重新校验权限、数据范围和最新状态，不以按钮显隐替代后台校验。

## 验证范围

权限目录精确资源及终端/角色保存回读；单/批共用与清空、归属等独立操作；8页3个删除入口；部分状态权限；失败后继续、回滚日志与状态、来源变化、组织及创建人范围隔离；显示ID、结果分组和刷新。首次失败和后续修复报告保留在本批次验证记录中。
