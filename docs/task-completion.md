# 任务完成流程

本文件是管理后台收尾编排入口；授权以用户级 AGENTS 与 Git Skill 为准。这里只维护项目能力，不改变业务、权限或数据语义。

## 正常路径

普通串行批次获得准确“任务完成”授权后，首选 `npm run task:completion -- deliver <batch-id> <准确任务40位SHA>`。该入口记录正式起点，核对登记、保护、备份与健康后串行完成推送、PR、PR CI、准确merge、本地main同步、main CI、最终交接和settle；每个阶段直接await前一阶段，不靠人工休眠轮询再接命令。只有刚创建事件尚未出现时有限等待查询，绝不dispatch或重跑CI；多个候选、失败、重跑、主线变化或保护不符均停止。源码修改不授权调用deliver；PR创建输出URL后仍须由调用方附加到当前对话。

调用方直接等待同一进程（可恢复终端会话），进度变化由它输出；不要另开watch、查询相同API或用45秒固定sleep轮询日志。若进程中断，从原准确参数恢复，已通过检查只核验原运行。数据库高风险保护锁仍走原受保护入口，不被普通自动链接管。首次自升级从已审查的准确本地候选进入PR流程，运行交接与清理仍只由已发布且main CI通过的版本承担。

1. 只有用户已授权准确批次正式交付时，立即执行 `npm run task:completion -- begin [请求的准确ISO时间]`，再执行 `plan` 一次核对模块、差异、验证缺口和独立资产。`begin` 只写本仓库私有阶段索引；`plan` 仍只读，不联网、不启动服务，也不是通过证明。没有请求时间时明确以首个正式收尾命令为计时起点，不补造此前耗时。
2. 按影响补必要本地检查并复用有效证据。验证工具/契约变化先 `npm run test:ci-reuse`：覆盖真实执行成功、严格复用成功、无法复用后原执行、真实执行失败四种路径，经过采集、路径选择、两份报告上传及最终汇总。源文件、报告缺失/损坏或未知模式均须阻断。定向通过后冻结准确候选，由可靠CI承担一次完整适用门禁，不先叠加本地相同全套。
3. 按原授权推送、PR验证、准确合并并同步本地main，保留模块提交和主线保护。普通串行交付不在PR等待期间提前同步集成；只有明确需要提前组合验收时才保留原同步入口。推送、创建/更新PR、合并及本地main同步分别用 `measure push|pr|merge|sync -- <原命令及参数>` 计时；通用prepare仍保留，不新增人工回执。索引只记阶段、候选与结果，不保存参数或环境值。每个准确运行只用 `npm run task:completion -- wait <run-id|pr|main> <head-sha>` 一个等待入口：pr/main按事件、登记分支和准确SHA定位，缺失或多个候选不猜测，改用准确运行编号；它不触发CI。等待器最多每分钟读取Job进度，仅报告变化，不再另开进度查询或watch；网络断开只恢复同一运行，最终两个汇总门禁仍必须读取成功。完整Jobs证据写入原索引，终端只输出摘要及下一阶段参数。开发期等待不计入begin后的正式收尾。
4. 准确main CI首次通过后，执行一次 `npm run task:completion -- final-handoff <main-sha>`。它刷新远程并统一计算main、固定集成、预览保留载体的目标版本，一次完成必要的集成合并/推送及干净预览载体快进，再使用main中已发布的兼容启动器停止所属任务进程、验证集成、释放锁并保留备份；同步子阶段自动计时。`handoff-plan <main-sha>`只读展示本地目标计划，正常执行不必另外重复调用。已有相同任务及集成HEAD的有效运行证明时，现场核对健康、数据身份和备份后复用，不重复调用启动器。脏目录、预览分叉、远端分叉或合并冲突保留现场，不强推、不覆盖；仅撤销本次发起的冲突合并。持有数据库保护锁的高风险任务继续使用原受保护同步/交接流程，本入口在任何载体更新前阻断，不抢锁或接管。长期预览不切换到任务目录或集成API，数据身份前后必须一致。CI失败先读取具体Job及原日志，再判断测试、等价、环境、上传或网络原因；需要补修时用 `repair-start <id> <failed-run> <category> <证据文件>` 关联真实失败、诊断日志指纹和补修起点。失败不因后续成功消失；新候选main CI通过才可结束补修，`settle` 自动确认已登记的修复。
5. main准确运行成功且交接完成后，执行 `npm run task:completion -- settle <batch-id> <main-sha> <run-id>`。它按顺序完成一次证据采集/汇总、当前运行与数据身份核对、已识别生成资产按内容保全、当前批次Git载体安全清理、登记关闭及统一回执；不另写多套人工审计脚本。CI证据存入Git common dir的 `task-delivery/<batch>/ci-<run>/`，内容/验证器/候选未变时复用，不重复下载或解析相同报告；变化或缺失即重新核验，不能凭聊天结论复用。独立Surefire报告也必须完整且与完整证据包一致。

`settle` 不自动授权推送、合并或清理，不启动/重建服务，必须在当前准确批次获得原“任务完成”授权后使用。它要求实时远程main、本地main、准确CI、候选树、已发布交接证明、预览身份和数据配置均匹配；任何必要证据缺失、未知/私密资产、脏工作区、锁或输入变化都会在清理前阻断。不强制移除Worktree，不删除数据库、容器、卷、备份、日志或依赖缓存。当前批次清理中断后仅凭自身阶段记录和完整保全证明从main锚点继续，不接管其他任务。`preserve` 与 `runtime` 保留为兼容入口，正常 `settle` 路径不重复调用。

统一回执位于 `task-delivery/<batch>/completion-receipt.json`；关闭后可 `npm run task:completion -- report <batch-id>` 查看。报告必须同时给出总墙钟、观察到的CI等待、服务端Job时间窗并集、CI结束后收尾时间、补修区间与原因/失败关联。并行区间只计一次，补修是总耗时的子集，不能相加；未记录的间隙单列，不推测为推理或执行。不同进程的等待与交接通过短时索引锁合并，不能覆盖彼此记录或抢占遗留锁。

耗时回执中的push/pr/merge/sync及最终交接都来自实际命令计时；等待与同步的并行区间取并集，命令间未记录时间继续单列，不承诺为零或归因为可节省成本。提前组合验收入口不纳入普通串行路径。

首次自升级仍区分已发布入口与已审查候选能力；新 `settle` 只在其准确版本进入main且通过必需CI后承担最终清理。没有实测证据不承诺固定分钟数，耗时目标不替代任何门禁或数据保护。

## 异常恢复与成本口径

- 阶段索引记录本机PID与主机身份；外部命令启动前先保存唯一启动意图，由独立POSIX进程组监督器记录组身份，前台后代继承该组。记录不含命令参数、环境值和输出。`recover`或deliver续接要求原所有者已不存在，且所有已登记前台进程组均已被系统证明不存在，才将运行中记录保留为中断失败；已证明退出的唯一启动记录封存，不因以后PID复用重复阻断。仍活跃的子进程、启动窗口不明、记录缺失、旧运行中阶段没有子进程证明及权限不足均保留现场，不自动杀进程。监督器退出不等于进程组退出，失败阶段的遗留子进程同样检查；独立启动的长期服务仍按原运行身份、健康及数据保护证明核验，不以进程组记录代替。活进程、未知/异机归属、无法确认的旧锁均拒绝，不凭超时抢占。只恢复本批次私有索引，不释放数据库/运行锁；Git和运行资源仍须通过原安全检查。中断执行停止时刻未知，区间明确标为恢复观察上限，不冒充实际CPU执行时间。
- 集成合并后先保存准确main、任务、旧远端及新本地提交证明，再推送。连接中断时仅允许同批次同一提交、同一工作区且远端仍为旧提交或该新提交时续推；未知领先/分叉继续拒绝，不重新merge、不强推。
- 报告先下载至本批次独立目录，完整验证后原子发布。部分下载和未通过验证的原包保留，不覆盖、不删除；恢复只重新获取缺失的准确运行报告。已证明包损坏不能静默当作成功，新的完整报告仍须原验证器通过；同一内容/策略证明有效时不重复下载。
- 回执原子写入；若批次已关闭但回执缺失，只从保留的成功证据、阶段记录及关闭登记重建历史回执，不再执行CI、合并或清理，也不冒充当前实时状态。
- 除CI失败人工诊断关联外，交接、证据下载、清理等阶段失败保留独立恢复关联与成本，只有同一阶段同一候选重新核验成功才结束恢复区间；原因未知就明确标注，不把恢复成功伪装为已查明根因。CI真实失败仍须原诊断及新候选成功，不自动原样重跑。
- 回执列出每段未归因间隙的起止、前后阶段，并单独列网络重连观察；并行和恢复区间取并集，不与总墙钟相加。登记层的remoteFreshnessProven=false仅表示登记命令本身不联网，最终回执另关联真实fetch与准确CI身份核验。

## 两分片均衡与定向性能诊断

`ci/e2e-shards.json`记录两次受信成功PR报告的运行编号、内容摘要、整文件分配和历史耗时估计；普通任务不自动重算。CI专用test:e2e:ci入口显式启用balanced，锁定Playwright使用公开`--test-list`选择完整文件（普通本地入口的原生过滤/分片兼容保持），保持文件内测试组、单worker、零重试和全部断言；原完整列表与两片的无重复并集仍由汇总强制核对。新文件、未知过滤条件或分片/worker变化失败，先审查计划，不接受缩减覆盖。分配计划完整字节纳入v4精确契约；旧v3报告不得补写为新契约成功。

既有报告器附加`e2e-performance.json`：记录用例总时长、钩子、导航、上下文创建及可用的容器CPU/内存观察，不读取页面数据、凭据或额外截图。步骤类别可能重叠，不能直接相加；runner进程资源不等于浏览器资源，缺失数据不能用于判断根因。仅用于区分初始化、导航和资源波动，未证明前不删除等待或共享测试状态。

## 工程输入索引维护

`npm run check:engineering-inputs`在CI规划前核对已审查输入清单。工具、工作流、分片计划及相关配置变更时，审查实际导入、CLI和文件读取者后显式更新`test-domain-manifest.json`；守卫不自动刷新。索引缺失或过期即阻断昂贵管线，未知依赖继续升级，不能改分类器或测试断言换取省略。普通业务/文档无相关工程输入变化且证明成立时，沿用已有适用范围。

## 长期预览契约

- 5175 为长期预览，5173/8080 为集成。预览数据身份唯一来源是 Git common dir 的 `preview-environment/environment.json`；配置、报告不得包含密码。数据库、媒体、备份均跨任务保留。
- 使用已安装且支持隔离数据的常驻服务。仓库旧版前台启动器尚未包含完整隔离数据实现，现在拒绝启动/降级安装，不得用它恢复到集成数据库；只读检查、停止和集成交接仍保留原兼容能力。此次不复制旧 Worktree 全套脚本，不迁移、重装或重启运行服务。
- `npm run task:completion -- runtime` 只读检查登记、备份与三个端点健康；它不替代具体预览 Worktree/API 身份核验，也不会启动环境。服务切换仍须现有启动器证明数据库与媒体相同，禁止自动重建缺失数据、覆盖媒体或切到集成 API。
- 预览不可用时 5175 返回明确503，`upstream=null`，HTTP与WebSocket均不回退集成。`useIntegration()` 仅保留兼容方法名，实际使预览不可用。
- 基建批次不读取、占用或切换业务预览；新业务批次只有在保留载体属于同仓、干净、恰为已发布主线且长期数据登记就绪时才可正常承接，否则仍拒绝抢占。运行脚本用隔离测试，现场环境仅只读核对。工具改动不自动成为业务预览的验收候选。

## CI 等价复用

PR 仍执行完整适用门禁；main 必需汇总 Job 保留。格式检查、前端静态、两个 E2E 分片及后端完整检查分别使用独立等价契约；工程域继续原执行，不将任何适用域标为不适用。

main 每个可复用 Job 先准备真实依赖，E2E 完成 `browser-image` 来源校验、`chrome-browser` 与 `chrome-dependencies`，再验证：

- 普通双亲合并的 base/head、合并后的完整代码树、准确已合并同仓 PR、受信工作流、该准确 head 最新的首次成功 PR 运行（合并后 API 的 PR 关联数组可能为空，独立核对合并父节点与树）；fork、失败、重跑、链式复用或报告缺失均拒绝。
- 格式和静态 Job 使用版本2契约；容器 E2E 使用版本5契约，旧版本报告不补写为新契约成功。全部 Job 保留实际 Node 二进制/版本、安装依赖内容、审查过的子进程环境和 Linux/x64/Ubuntu24 平台；事件身份与API令牌不进入测试进程。
- 资源采用已支持的 GitHub-hosted 四逻辑核、至少16GB可见内存规格。CPU型号和内存原始字节仅保存在 `environmentObservation` 诊断字段，不参与相等比较；规格不符、其他架构/系统、自托管或未知来源均回原门禁。该契约仅支持当前普通功能检查，不适用于性能、内存耗尽、GPU或硬件指令专项；新增此类测试必须先审查契约或禁用相应复用。
- 格式 Job 只比较上述共同输入，不要求内核补丁、runner镜像版本、全部系统包或字体相同。静态 Job 另外保留实际runner镜像、内核、系统包及OS标识文件；E2E 使用精确容器摘要和来源记录替代宿主机用户空间镜像标签，另保留宿主内核、完整容器系统包、OS标识、实际Chrome二进制/内容及字体配置；不得跨虚拟机/容器契约复用。当前不继续收窄静态/E2E的系统库证明；后端采用下述独立契约，工程域不复用。
- 同一可复用 Job 前后核对相关输入稳定。实际环境无法证明或输入不符即运行原门禁，不将容量不同、诊断采集或API故障误报为测试已通过。
- 源报告原样保留，记录来源运行与原始身份，只重绑定经过验证的合并身份；汇总仍核对完整测试清单、分片并集、单测及守卫、零跳过零重试，不能伪造当前已重新执行。
- 正常执行或复用结束再次确认相关输入稳定。任何等价探测失败回原执行；报告验证失败仍阻断必需门禁。下载或API错误是复用未命中，不是测试重跑。

首次采用时若源 PR 尚无新格式证明，main 正常全量；不为得到命中降低条件。节省时间以真实命中和整个流水线关键路径报告，不把并行 Job 耗时相加；main 后端仅在下述全部条件成立时复用，否则完整执行，因此不能承诺 main 零等待或固定分钟数。历史报告只可作诊断样本，不替代当前候选正式证明。节省比例不预先承诺。仓库变量 `CI_EQUIVALENCE_DISABLED=true` 可立即回退全部原执行，也可逐Job撤销复用；不会移除必需汇总或覆盖断言。

## 异常路径和保留边界

Linux、跨平台矩阵、模拟器仅用于真实失败诊断；先最小复现和定向修复，再提交完整候选。未知资产、私密文件、冲突、数据或锁异常保留现场；已有准确授权不重复询问，安全工具审批不绕过。不清理数据库、容器、卷、备份、日志、依赖缓存或其他任务资产，不改变生产发布授权。

## 契约变更验收

- 前置诊断覆盖真实 depth-one 浅克隆、五类 Job 获取/回放、后端完整报告汇总和两分片汇总；CPU跨型号及规格内容量差异允许，相关依赖、浏览器、原始报告、来源或候选改变必须拒绝。漏项、重复、跳过、重试仍阻断汇总。
- CI 规划阶段在无 `node_modules`、无Docker和无服务条件下完成诊断，再开启原适用门禁；本地验证计划显式显示这一前置步骤。完整工程清单仍执行，不用诊断替代门禁。
- 候选齐备后按风险运行一次必要完整门禁。成功结果按相关输入复用；真实失败保留并归因修复后重验，不因耗时目标跳过必需检查。不增加分片、不缩减分类器、不关闭main工作流；后端复用仅按下述独立契约实施。

### Chrome 与系统依赖准备

两个 E2E 分片使用 `scripts/ci-chrome-preparation.mjs`，保留 `channel=chrome`、两分片及 `workers=1`。`chrome-browser` 从 Google 官方 VersionHistory 获取 Linux Stable 最新版本，并保留已交付版本 `156.0.8078.47` 作为禁止降级的最低基线；实际 Chrome Stable 软件包与二进制版本一致且不低于当前基线才复用，预构建容器版本不足时明确失败，要求独立更新镜像；普通 CI 不补装、不重建，也不降级。旧虚拟机入口仍保留原安装能力。版本信息缺失、网络或安装失败均停止，不接受旧版本作为回退。

独立镜像构建通过当前锁定 Playwright 的完整 `install --with-deps chrome` 准备正式浏览器、全部字体和系统依赖；两个容器分片显式使用 `LANG=C.UTF-8`、`LC_ALL=C.UTF-8`，确认 `locale charmap` 为 UTF-8；这些值仍纳入原有精确环境指纹。普通测试中的 `chrome-dependencies` 使用相同锁定清单的公开 `install-deps chrome --dry-run` 确认没有缺失依赖，并与镜像内完整包、字体和浏览器内容清单逐项核对，同时验证实际 Chrome 可启动、中文 Blob 下载名保持完整且版本未被改写。不得删除字体、换用 Chromium 或改为只检查文件是否存在。浏览器准备、依赖准备及测试分别计时，环境报告记录复用或安装结果。

仅在 Ubuntu 24.04 x64 的 GitHub CI 临时环境中，将已确认慢下载的 Azure Ubuntu 镜像地址替换为 Ubuntu 官方 HTTPS 地址，兼容镜像列表、旧 sources.list 与 deb822 文件；保留全部仓库、组件、签名与校验设置。APT 连接超时30秒、网络下载重试1次，索引不完整即失败；这些仅控制软件下载，不增加测试重试或放宽失败断言。配置异常保留失败，不能静默跳过依赖。浏览器目录、字体、完整系统包及其余适用版本的等价指纹维持原有精确比较；环境输入不同就重新执行适用测试。

### 后端独立等价契约

`backend_full` 使用 `backend-maven-testcontainers-v1`。PR 始终实际执行原命令 `mvn -B test checkstyle:check spotbugs:check jacoco:report`；main 只复用准确同仓成功 PR 的首次执行，保留 `Backend full checks` 和必需 `Backend quality` 汇总，沿用严格合并父节点、完整代码树、受信来源和禁止链式复用要求。不新增后端镜像、不变更业务测试、断言、fork 数、覆盖或数据库保护。

- 前置记录和执行后闭包必须证明实际 Java 21 JDK 内容、Maven 安装内容及版本、用户/全局 settings 和 toolchains 内容指纹、Node、Ubuntu24/x64、现有四核至少16GB资源类、内核和系统包、Docker引擎及运行配置、后端/验证器相关源码与环境一致。CPU型号及内存字节仍仅作诊断。原始配置及敏感环境只记哈希，不复制配置内容；测试子进程不继承GitHub事件身份和API令牌。
- 成功源运行保存 Maven 仓库实际 JAR/POM 清单及逐文件内容哈希。它是保守依赖闭包，不使用整个跨项目缓存目录的时间戳或缓存键作为成功证明。main 检查同一清单的实际内容，缺失项仅从 Maven Central 无凭据下载并按源哈希验证，已有内容不符不覆盖；私有来源、SNAPSHOT、动态版本、未知 Maven 扩展/配置及外部 Testcontainers 配置无法证明时回原门禁。Testcontainers 首次连接自动保存的 `docker.client.strategy=org.testcontainers.dockerclient.UnixSocketClientProviderStrategy` 只在值完全匹配且没有其他配置键时，按已验证的干净 Linux Unix socket 默认策略记录；生成注释/时间不属于运行输入，其他 provider、远程 Docker、镜像替换或检查豁免均拒绝。不归档整个 Maven 缓存或凭据文件。
- 测试声明的 MySQL 镜像及 Testcontainers 辅助镜像记录实际 image ID 与 RepoDigests。main 解析同名镜像并精确比较；标签相同不代表等价，变化即回原门禁。仅 CI 临时 Runner 拉取镜像，不连接持久预览或集成数据库，不启动复用测试容器。
- 源运行保留 Surefire 全部原始报告、JaCoCo 原始执行数据与 XML/CSV/HTML、Checkstyle及SpotBugs结果，绑定实际编译类内容指纹、完整文件清单和哈希。源执行仍检查报告新鲜度、测试类覆盖、零失败/跳过/重试；归档回放验证可信原始身份和字节，不修改时间冒充新执行。完整报告和依赖清单进入 `ci-backend-full`，原 `ci-backend-reports` 名称、保留期和缺失阻断保持。采集、默认解析和验证的路径由 `ci-report-contract.mjs` 统一定义；CI的 `report_sources` 步骤按真实 `CI_EVIDENCE_DIR` 输出两份上传来源：真实执行（含失败）读取原target，复用读取已验证共享证据目录。不得在YAML另写第二份条件路径，也不能要求未重新执行的target报告或忽略缺失。
- main 汇总重新校验原始报告完整性、当前同树测试清单和原始结果，不仅看汇总数字或绿色状态。输入采集、API、下载或等价证明缺失时运行原完整门禁；真实失败、损坏或遗漏不能成为成功。`CI_EQUIVALENCE_DISABLED=true` 仍可回退原执行。
- 前置 `test:ci-reuse` 包含后端允许、拒绝、Maven内容补齐、报告回放与最终汇总诊断；无需 Maven、Docker、服务或 `node_modules` 即可执行。定向通过后固定候选，由 PR 负责一次完整适用 CI，不在此前叠加本地相同全量。新契约必须产生真实新格式源证据，旧报告不补写指纹。
- 发布后分别记录 PR 实际执行、main 探测/依赖及镜像准备、命中或回退原因、源报告及当前身份和总关键路径。镜像/依赖准备存在成本，不预承诺固定命中率或分钟数。真实API、迁移、持久数据备份和运行交接按原规则单独验收，测试证据不能替代。

## 本地就绪、诊断去重与预构建测试

普通 `verify:delivery` 实际执行先以只读API证明本仓库工作流启用、main严格必需检查和管理员保护；证明有效时仅作本地格式、静态、直接受影响用例及工具前置诊断，完整适用域仍由原分类器保守判定并交准确候选CI。登录、权限、生产API/后端、迁移及运行配置变化仍保留原本地风险验证，不由CI可用证明免除。CI不可证明则执行原本地完整回退；`verify:local`始终保留完整验证。`--list`不访问API，明确展示保守回退而非伪称实时CI可用。收口统一入口不会额外再调用一遍本地完整执行器。

所有scripts、ci配置、Vite/Playwright、包及适配入口采用同一前置诊断识别；先失败则不启动昂贵检查。前置报告完整上传，工程Job仅在同次首次运行、准确候选/树/全部源码、Node和Git实际二进制、系统包/内核、资源类、Git配置及脱敏子进程环境精确一致时复用。前置诊断在独立浅克隆且无法解析安装依赖的源码副本中执行，不因工程Job有node_modules而臆断等价。原始事件重建结果必须一致；工程报告保持原完整文件和用例全集，由原始前置报告与剩余实际执行形成无重复并集，最终汇总再次核验来源和原始事件。报告缺失或等价无法证明时执行原工程全集；前置失败仍先阻断。记录不含凭据或原始Git配置值。

E2E保留两分片和单worker。默认预构建应用及登记的全部HTML入口，`ci/e2e-app.json`对新增/遗漏入口阻断；业务和官方参考页使用真实构建产物。原生样式隔离用例的断言完整移至`native-style-isolation.spec.ts`，专用开发服务执行，不使用grep隐去或重复用例；总语义用例仍为657，文件因专项分离为42。新增用例按实际全集守卫正常增长，不永久硬编码657作为覆盖上限。构建源、实际产物、入口/专项策略和分片计划均精确核验；旧v4证据不能授予v5复用。CI先准备并核验实际产物再探测复用，首次新契约没有受信源证明时运行原完整适用门禁。

附加资源观察仅采样本次测试后代进程的CPU与RSS，区分服务、Chrome和worker；不记录进程参数、环境值、请求URL、正文或页面数据。不支持的平台明确不可用；短命进程可能漏采，RSS可能重复计算共享页，不将缺失观察或累计类别当作因果证明。测试端口不使用5173/5175/5176，不能抢占现有监听。

本次本机11项代表用例两组交替对比：开发态27.4/25.8秒，预构建18.8/18.6秒，全部通过。此数字不包含每次正式构建成本，不折算成CI承诺；CI实际总关键路径和命中须正式交付后报告。开发阶段保留所有失败与修复后的证据，不把样本通过当作全部657用例已执行。

## 交付状态与统计口径（v2）

唯一最终状态由同批次阶段记录、关闭登记、最终main CI身份及原正式回执共同证明：本地完成、PR通过、main通过、运行交接和清理关闭分别显示，不能互相替代。`status <batch>`只读查询；`backfill <batch>`仅为已证明完整关闭的批次原子生成`completion-status.json`派生索引，不访问远程、不重新下载或运行测试，也不执行Git、运行交接或清理。正式settle写好回执后自动回填同一索引；闭合回执缺失按原保护恢复，合法重建后保留旧状态索引，普通源回执变化仍拒绝覆盖。原回执、原事件、首次失败和诊断指纹不改写。关闭批次状态明确为历史证明，不冒充当前远程实时核验。源码中的冻结候选/本地验收清单须标为阶段快照，回填引用最终记录，不因更新状态再运行全量验证。

人工暂停先调用`pause-record <batch>`记录请求界限，再停止已核实身份的当前执行器；该记录入口只记时间和当前阶段，不操作进程、Git、CI、服务、锁或数据，不能当作执行器已停止。已启动远程CI默认可继续。恢复时`deliver`自动结束已记录暂停，也可用`resume-record <batch>`显式记录；恢复仍执行原进程归属、子进程退出和资源安全检查，不凭记录跳过保护。

总墙钟包含暂停，不重置。`pauseMs`仅在完整记录起止时给出；历史缺失显示未知，`recordedPauseMs`只表示已记录部分，禁止估算扣除。`ciWaitMs`保留原观察窗，`ciJobWindowMs`是远端Job时间窗并集；完整暂停记录下另给`activeCiWaitMs`，扣除已记录暂停。未知中断上限仍明示，不能当作实际执行时长。

`restorationWindowMs`保留恢复观察窗口；`recoveryMs`扣除已记录CI等待与暂停。自动stage-restoration不再计作代码补修。实际补修保留`repairWindowMs`，`repairMs`扣除等待与暂停；代码、环境/网络、未分类分别给出，只有明确`repair-start ... <evidence> code`才计代码补修，不从旧类别猜测。省略类型的旧补修记为未分类，不伪报代码修复。各类是观察区间，不是CPU时间，可能与远端CI重叠，禁止累加到总墙钟。原始回执仍保留旧统计，v2派生视图明确标记版本与来源哈希。

交接运行指纹使用独立的纯路径分类，不逐文件执行整仓业务关联审查；完整业务影响和旧行为守卫仍按原入口执行。交接保留前后运行快照，源码、配置或容器身份变化仍会使证明失效。

正式交接须通过现有已安装且支持隔离数据的兼容预览服务，承接到准确主线的 `codex/preview-current`。预检只在集成和备份有效、预览归属已知时允许预览暂缺；停止当前任务后显式启动全栈承接，核验目录、分支、模式、隔离 API、健康和实际数据绑定。健康承接只复核；其他任务占用、未知状态、缺少兼容启动器、启动失败、503 或身份/数据不符均阻止完成与清理。不得重装服务、回退集成 API 或重建数据；直接调用收口入口也必须再次证明承接有效。

## 受控执行效率

- 等待器在运行身份、候选、首次尝试及 Job 终态均核实后，立即记录失败并退出等待。整轮仍在运行时保留真实 `in_progress` 和失败 Job 身份，不取消其他 Job、不重跑、不进入合并或清理；修复须关联原失败与新候选。
- 本地 `test:scripts:files` 若与必需诊断重叠，先执行完整诊断，再执行差集；正式就绪检查与定向入口传递同一次执行的 UUID 及严格证据，不另开一轮诊断；同一执行内核对源码、依赖、环境、原始报告与完整并集。诊断失败、证据缺失、报告损坏和候选变化直接阻断，不用额外重验制造成功。
- CI 使用精确 Node 补丁基线，静态检查与两组 E2E 使用同一个已发布摘要镜像。静态环境使用 v3 独立契约，旧 v2 不能重解释为成功；内核、实际工具链、包、输入、权限隔离及环境差异仍回退原执行。固定镜像不代表宿主内核固定。
- `scripts/engineering-impact.json` 只登记明确审查的交付控制工具。只有工程输入指纹、完整反向拓扑、实际外部入口及静态图无法覆盖的反射读者集合/内容均匹配时，分类器及定向入口才使用工程影响域；仍执行完整工程回归和必需汇总。未知输入、遗漏或新增消费者、动态外部消费者、依赖变更、域扩张及共享验证/CI/权限/迁移变更全部回原完整适用门禁。修改登记或证明实现本身也走全量，不能自动刷新证明换取缩小覆盖。
