# 任务完成流程

本文件是管理后台收尾编排入口；授权以用户级 AGENTS 与 Git Skill 为准。这里只维护项目能力，不改变业务、权限或数据语义。

## 正常路径

1. 在准确批次 Worktree 执行 `npm run task:completion -- plan`。一次读取登记模块、差异、待保留资产与执行边界；后续仅在相关状态变化时补查。该命令不联网、不启动服务、不修改文件，也不是交付成功证明。
2. 按影响补必要本地检查，复用执行器证明有效的证据。验证工具或复用契约变化先运行 `npm run test:ci-reuse` 做纯 Node/Git 定向诊断；本地完整执行器和 CI 规划 Job 会在昂贵门禁前执行同一入口，失败即停止。定向定位通过后固定候选，执行一次必要完整门禁；不要先手动跑一遍工程全量，再让完整执行器重复跑同一工程全量。定向诊断不替代正式完整覆盖。可靠 CI 承担最终完整适用门禁；高风险、验证器修改、真实环境缺口或 CI 不可靠时补原本地完整/专项验证。不同阶段的必要验证不机械合并成重复，也不因追求“一次”隐去失败。
3. 获推送授权后推送并触发 PR CI。使用 `npm run task:completion -- wait <run-id> <expected-head>` 一个等待入口；网络中断只重连同一运行，不重新跑测试。检查准确提交、首次执行与两个必需汇总门禁。完整覆盖、零跳过与零重试由 CI 的原报告验证器负责，等待器不替代它们。
4. 按原保护规则合并准确任务，保留模块提交，同步本地主线；集成合入准确任务或已批准组合，不把滚动集成整体合入 main。
5. 只读核对版本、路由、健康、锁和备份；已达目标不重启。运行身份改变时补真实证明。停止不再使用的所属任务进程，不停止承接长期预览的数据服务。
6. 核对第一步资产清单。确需保留的已识别生成文件可执行 `npm run task:completion -- preserve`，存入 Git common dir 的 `task-assets/<batch>/`。按内容寻址保留一份、记录路径与校验；不压缩多套相同目录、不删除源文件、不提交或推送。未知文件、私密输入、内部依赖和异常链接会阻断自动保全；保留原目录，不能用可再生成作为删除授权。该入口不要求每次运行；若没有待保留内容，不创建额外归档。
7. 成果已推送、已合并且目录干净后，按原授权安全移除准确 Worktree 和本地/远程分支，复核受影响资源并 `task:batch -- close`。一份交付摘要关联原始证据即可，不另造多套人工回执。批次索引不代替实时 Git、CI 与运行证据。

## 长期预览契约

- 5175 为长期预览，5173/8080 为集成。预览数据身份唯一来源是 Git common dir 的 `preview-environment/environment.json`；配置、报告不得包含密码。数据库、媒体、备份均跨任务保留。
- 使用已安装且支持隔离数据的常驻服务。仓库旧版前台启动器尚未包含完整隔离数据实现，现在拒绝启动/降级安装，不得用它恢复到集成数据库；只读检查、停止和集成交接仍保留原兼容能力。此次不复制旧 Worktree 全套脚本，不迁移、重装或重启运行服务。
- `npm run task:completion -- runtime` 只读检查登记、备份与三个端点健康；它不替代具体预览 Worktree/API 身份核验，也不会启动环境。服务切换仍须现有启动器证明数据库与媒体相同，禁止自动重建缺失数据、覆盖媒体或切到集成 API。
- 预览不可用时 5175 返回明确503，`upstream=null`，HTTP与WebSocket均不回退集成。`useIntegration()` 仅保留兼容方法名，实际使预览不可用。
- 基建批次不读取、占用或切换业务预览；新业务批次只有在保留载体属于同仓、干净、恰为已发布主线且长期数据登记就绪时才可正常承接，否则仍拒绝抢占。运行脚本用隔离测试，现场环境仅只读核对。工具改动不自动成为业务预览的验收候选。

## CI 等价复用

PR 仍执行完整适用门禁；main 必需汇总 Job 保留。仅格式检查、前端静态与两个 E2E 分片支持本轮审查过的契约，后端和工程域继续原执行；这不是把它们标为不适用。

main 每个可复用 Job 先准备真实依赖，E2E 完成 `browser-image` 来源校验、`chrome-browser` 与 `chrome-dependencies`，再验证：

- 普通双亲合并的 base/head、合并后的完整代码树、准确已合并同仓 PR、受信工作流、该准确 head 最新的首次成功 PR 运行（合并后 API 的 PR 关联数组可能为空，独立核对合并父节点与树）；fork、失败、重跑、链式复用或报告缺失均拒绝。
- 格式和静态 Job 使用版本2契约；容器 E2E 使用版本3契约，旧版本报告不补写为新契约成功。全部 Job 保留实际 Node 二进制/版本、安装依赖内容、审查过的子进程环境和 Linux/x64/Ubuntu24 平台；事件身份与API令牌不进入测试进程。
- 资源采用已支持的 GitHub-hosted 四逻辑核、至少16GB可见内存规格。CPU型号和内存原始字节仅保存在 `environmentObservation` 诊断字段，不参与相等比较；规格不符、其他架构/系统、自托管或未知来源均回原门禁。该契约仅支持当前普通功能检查，不适用于性能、内存耗尽、GPU或硬件指令专项；新增此类测试必须先审查契约或禁用相应复用。
- 格式 Job 只比较上述共同输入，不要求内核补丁、runner镜像版本、全部系统包或字体相同。静态 Job 另外保留实际runner镜像、内核、系统包及OS标识文件；E2E 使用精确容器摘要和来源记录替代宿主机用户空间镜像标签，另保留宿主内核、完整容器系统包、OS标识、实际Chrome二进制/内容及字体配置；不得跨虚拟机/容器契约复用。当前不继续收窄静态/E2E的系统库证明，不扩展后端或工程域复用。
- 同一可复用 Job 前后核对相关输入稳定。实际环境无法证明或输入不符即运行原门禁，不将容量不同、诊断采集或API故障误报为测试已通过。
- 源报告原样保留，记录来源运行与原始身份，只重绑定经过验证的合并身份；汇总仍核对完整测试清单、分片并集、单测及守卫、零跳过零重试，不能伪造当前已重新执行。
- 正常执行或复用结束再次确认相关输入稳定。任何等价探测失败回原执行；报告验证失败仍阻断必需门禁。下载或API错误是复用未命中，不是测试重跑。

首次采用时若源 PR 尚无新格式证明，main 正常全量；不为得到命中降低条件。节省时间以真实命中和整个流水线关键路径报告，不把并行 Job 耗时相加；main 后端仍完整执行，因此不能承诺 main 零等待或固定分钟数。历史报告只可作诊断样本，不替代当前候选正式证明。节省比例不预先承诺。仓库变量 `CI_EQUIVALENCE_DISABLED=true` 可立即回退全部原执行，也可逐Job撤销复用；不会移除必需汇总或覆盖断言。

## 异常路径和保留边界

Linux、跨平台矩阵、模拟器仅用于真实失败诊断；先最小复现和定向修复，再提交完整候选。未知资产、私密文件、冲突、数据或锁异常保留现场；已有准确授权不重复询问，安全工具审批不绕过。不清理数据库、容器、卷、备份、日志、依赖缓存或其他任务资产，不改变生产发布授权。

## 契约变更验收

- 前置诊断覆盖真实 depth-one 浅克隆、四类 Job 获取/回放和两分片汇总；CPU跨型号及规格内容量差异允许，相关依赖、浏览器、原始报告、来源或候选改变必须拒绝。漏项、重复、跳过、重试仍阻断汇总。
- CI 规划阶段在无 `node_modules`、无Docker和无服务条件下完成诊断，再开启原适用门禁；本地验证计划显式显示这一前置步骤。完整工程清单仍执行，不用诊断替代门禁。
- 候选齐备后按风险运行一次必要完整门禁。成功结果按相关输入复用；真实失败保留并归因修复后重验，不因耗时目标跳过必需检查。四分片、分类器缩减、关闭main工作流或后端复用不在本轮范围。

### Chrome 与系统依赖准备

两个 E2E 分片使用 `scripts/ci-chrome-preparation.mjs`，保留 `channel=chrome`、两分片及 `workers=1`。`chrome-browser` 从 Google 官方 VersionHistory 获取 Linux Stable 最新版本，并保留已交付版本 `156.0.8078.47` 作为禁止降级的最低基线；实际 Chrome Stable 软件包与二进制版本一致且不低于当前基线才复用，预构建容器版本不足时明确失败，要求独立更新镜像；普通 CI 不补装、不重建，也不降级。旧虚拟机入口仍保留原安装能力。版本信息缺失、网络或安装失败均停止，不接受旧版本作为回退。

独立镜像构建通过当前锁定 Playwright 的完整 `install --with-deps chrome` 准备正式浏览器、全部字体和系统依赖；普通测试中的 `chrome-dependencies` 使用相同锁定清单的公开 `install-deps chrome --dry-run` 确认没有缺失依赖，并与镜像内完整包、字体和浏览器内容清单逐项核对，同时验证实际 Chrome 可启动且版本未被改写。不得删除字体、换用 Chromium 或改为只检查文件是否存在。浏览器准备、依赖准备及测试分别计时，环境报告记录复用或安装结果。

仅在 Ubuntu 24.04 x64 的 GitHub CI 临时环境中，将已确认慢下载的 Azure Ubuntu 镜像地址替换为 Ubuntu 官方 HTTPS 地址，兼容镜像列表、旧 sources.list 与 deb822 文件；保留全部仓库、组件、签名与校验设置。APT 连接超时30秒、网络下载重试1次，索引不完整即失败；这些仅控制软件下载，不增加测试重试或放宽失败断言。配置异常保留失败，不能静默跳过依赖。浏览器目录、字体、完整系统包及其余适用版本的等价指纹维持原有精确比较；环境输入不同就重新执行适用测试。

### 独立预构建测试容器

- 发布入口 `.github/workflows/browser-image.yml` 独立维护 Ubuntu24.04/amd64、Node22、正式 Chrome 与完整 Playwright 字体依赖。仅显式 dispatch 才构建；Quality Gate 与任务完成不调用发布器。镜像不包含应用源码、凭据、数据库或持久数据，测试进程以 UID/GID 1001 运行、移除全部 capability 并禁止提权；GitHub 默认挂载的 Docker socket 必须实测不可访问，异常即阻断。
- `ci/browser-image.lock.json` 是测试镜像唯一来源记录：固定 GHCR 摘要、发布源码 SHA/运行、两个官方基础镜像摘要及完整实际工具链清单。两个分片都由 scope 读取同一锁；不得使用 latest、可变标签、仓库变量覆盖或不明镜像。镜像更新需先单独发布、验证新摘要，再审查登记文件；不会因普通任务推送或收尾再次构建。
- 发布任务才有 packages:write；测试仅 packages:read。PR 事件不能发布镜像；首次引导发布已完成并移除临时 push 触发入口；后续只允许显式独立更新。正常浏览器仍实时检查官方 Stable 基线，镜像变旧时要求独立更新，不能降低基线换取命中。
- 容器 E2E 使用 v3 独立契约；实际摘要、来源记录、Node 二进制、依赖、完整系统包、OS/字体/Chrome内容、宿主内核及子进程环境都必须精确一致，资源规格保持四核且至少16GB。不将宿主 ImageVersion 当作容器版本，宿主实际镜像来源由 CI 初始化原始日志保留。
- 发布器在另一台新 hosted runner 显式计时冷拉取，保存 `browser-image-cold-pull`。每次正式 CI 的实际容器拉取/初始化耗时读取原始 `Initialize containers` Job日志；运行期 `browser-image`、`chrome-browser`、`chrome-dependencies` 与测试分别计时。发布冷拉取不能冒充每次实际 CI 拉取，浏览器复用与测试报告复用分别报告。
- 两分片、workers=1、完整清单并集、前后端必需门禁、零跳过/重试、首次成功与数据保护保持不变。首次容器候选执行完整适用 CI，此后仅由执行器证明有效的同契约证据复用。

镜像独立更新示例：审查工具链定义与官方基础摘要后，显式运行 `gh workflow run browser-image.yml --ref <已推送的准确分支>`。发布及冷拉取成功后下载该运行的 `browser-image-release`，将发布记录登记为 `ci/browser-image.lock.json`；核对来源与依赖一致，再运行该候选适用 CI。发布成功不会自动改写锁文件或主线，也不自动清理旧镜像。
