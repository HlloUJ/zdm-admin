# 配件管理

2026-10-22 用户确认：三端配件管理与运营端配件价格配置一起实现，界面、交互和业务规则与成品现货对应模块一致。

## 范围

- 供应链端负责图文、基础属性、销售规格、供货成本与数量的采集维护。
- 运营端沿用成品现货的运营仓库、平台价格、上下架、日志及回收站流程。
- 门店端沿用商品中心选品、本店商品、售价、上下架、日志及回收站流程。
- 发布与编辑保留图文描述、基础信息、销售信息三个分区；主图、视频、宝贝详情保持原有必填和媒体交互。
- 配件使用既有配件分类、配件属性模板与 SKU 组合；版本引用及历史字段处理保持一致。
- 运营价格配置增加配件价格配置 Tab，指导价、合伙人系数、自动与手工价格规则和成品现货一致；数值独立维护。
- 门店既有配件分类、配件售价配置接入配件商品，分类停用、失去末级资格或清除系数时按原有规则冻结自动售价。

## 数据与权限边界

- 平台分类及模板按既有授权作为共用配置读取；配件商品和三端协作行为复用现有成品现货作用域，不扩大组织可见范围。
- `accessory_products`、规格、商品属性值、指导价、合伙人价格与配置、操作日志以及门店选品/售价/日志使用独立表。V164 只创建空表，不复制成品商品、价格配置或角色授权。
- 商品媒体及失效快照使用独立 `ACCESSORY_*` 业务域；底层媒体服务共用，引用与释放按事务和全平台引用数保护。
- 三端权限使用 `admin.accessory-management`、`supply-chain.accessory-management`、`store.accessory-management`；运营价格配置使用 `admin.product-data-center.markup-configuration.accessory`。
- 统一目录、终端分配、角色、前端和后端消费同一资源编码。新资源进入候选目录，不自动授予既有普通角色或扩大终端上限。

## 实现与保留约定

- 三端页面复用成品现货现有组件，通过组件注入明确绑定商品域、API、权限及路由；独立路由组件确保切换模块时重新创建页面状态。
- 后端配件实体、服务、生命周期与日志独立；成品现货原有 API、表、默认值、权限和流程保留。
- 公共类目、属性、供应商、门店级别及组织删除预检增加配件引用保护，防止删除仍被配件使用的基础配置。
- 迁移在隔离测试库验证后，通过已配置的长期预览启动器完成备份、锁和 Flyway 检查；不恢复、重建或清空预览数据。
- 精确业务差异登记在现有视觉契约清单中，原指纹和守卫保持。SpotBugs 仅为与现有成品类相同的两个 Spring 注入类登记相同 `EI_EXPOSE_REP2` 例外，业务值对象的防御性复制检查不变。
