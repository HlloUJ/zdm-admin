# 计时中断与交接恢复

本次工程修复独立于批量上架、批量删除、权限合并业务候选。不切换业务预览，不改变质量门禁、业务约定或并发写入保护。

## 失败原因与处理

- 原生 `turn_aborted` 原先未被识别，已中断轮次被保留为运行中。现在按原生事件时间记录 `interrupted`，与正常完成区分；结束时间缺失时不猜测。
- 旧观察器可能已消费中断事件。恢复时仅一次回读登记源的已消费前缀，为已登记且未结束的轮次补录真实终止元数据，保持游标、授权标识及原始事件不变。
- 新建批次或绑定新聊天不能采用已经完成/中断的原生轮次；旧记录若授权轮次早于批次登记即已终止，保留原边界，将整批总时长标为不可用，不把多天间隙算作开发耗时。
- 验证入口使用尽力观测：异常输出明确原因，质量检查继续执行并保留真实退出码。严格绑定、授权标识防篡改与收尾证明仍独立校验，不以计时告警豁免任何质量门禁。
- 只有登记开发 Worktree 参与当前批次观测；其他工程 Worktree 不读写该业务计时记录。显式历史批次报告仍可按批次查询。
- 常驻观察器核对代码摘要，升级前证明主机、PID、可执行路径和随机令牌归属，仅停止准确旧进程；无法证明退出则保留现场。相同版本复用原观察器。

## 保留边界

恢复聊天仍须显式串行交接；没有原生结束/中断证据的前任轮次继续拒绝接管。不依据时间长短、空闲推断或自然语言内容自动授权。源文件身份变化、截断、标识篡改及未知结束时间保留为不完整证据。中断的最终回复不得标为成功完成。

## 验证

专项覆盖原生中断、跨聊天交接、旧游标恢复、陈旧授权拒绝、真实活跃前任拒绝、来源损坏、授权防篡改、跨工作区隔离、真实验证 CLI 失败退出码及观察器升级。工程完整检查沿用项目既有执行器，不放宽断言、重试、零跳过或 CI 标准。

单一活跃批次登记目前由业务任务占用，因此此独立工程分支保留自有 Git 载体与本说明，不覆盖业务登记；正式交付另按准确任务范围处理。

## 历史缺失收尾与版本兼容补齐

收尾仍核对原始授权标识、来源完整性、未结束验证及并发轮次；仅将已经确认的 `authorization-turn-ended-before-registration` 历史边界缺失从计时完整性阻断中移出。交付状态可以完成，计时状态继续保持不完整、总耗时为 null，原授权时间与原始记录不重建。其他未知或损坏证据仍拒绝放行。

前一阶段计时持久化格式升级至 v2，汇总标记为 timingVersion 4。新版可以读取 v1；首次写入升级时按内容摘要保留原始时间线与原汇总快照。真实 v1 计算器遇到 v2 时间线时会在发布汇总前拒绝处理，不能重新计算并覆盖虚假的总耗时。另保留新版独立解析游标，旧写入者推进旧游标也不能隐藏中断事件。历史正式交付回执保持原样。

两份原版 v1 工具作为测试夹具保留，来源为主线提交 `439cf96cdbf7b07b2aa18ad07570d50a084e6014`，仅用于实际跨版本读写回归。工具正式交付和统一入口前不升级活跃业务的共享记录；本工程分支不替换业务源码或预览。

## 升级异常恢复补齐

当前写入格式为 v3、汇总为 timingVersion 5，读取兼容 v1/v2。只读报告须同时核对发布清单、时间线、汇总及原授权标识的摘要；不匹配时明确不可用，不展示旧总耗时。发布顺序为：校验原始快照、发布未知状态汇总、发布时间线、发布新汇总、最后提交发布清单。暂存文件完整写入、校验并同步磁盘后才发布；文件与目录均同步。中断产生的暂存文件不作为成功证据。

原始快照使用内容寻址且仅创建不覆盖；已有快照必须是普通文件且与原始字节一致。首次绑定先保留初始化记录，再发布原授权标识，未完成首次提交可凭校验后的记录继续；已提交时间线丢失不能用初始化记录重建。重复验证／中断记录仅接受完全相同的内容，冲突仍拒绝。

写锁仅在同主机、PID 已被操作系统证明退出时恢复，先保留死锁原文；活跃、异机、损坏、身份未知的锁继续保护。恢复者通过 Node 内置 SQLite 事务串行化，恢复进程被杀后由操作系统释放事务，不依靠超时抢锁。正常写入继续共用原 writer.lock，不替代原批次并发写入保护。没有新增运行依赖；当前本地 Node 24 与 CI Node 22.23.4 提供内置 SQLite。
