# 已交付任务的本机清理

管理后台磁盘清理 V2 沿用 `com.zdm.admin.manifest-cleanup` 的北京时间 01:00、13:00 日程。发布后的运行包从准确 main Git 对象部署。宿主恢复后只补最近一个日历时段。旧锁及正在执行的时段需有原进程和子进程组的结束证明，跨时段也保留未知结果。

切换前使用独立 Git 仓库和临时 Docker 资源验证正式交付识别、外部嵌套副本、数据库及容器卷回收、1 GiB 逻辑预算与中断接续、引用释放与保护。核实正式定时器指向已发布 V2 运行包后，配置 `.git/task-cleanup/policy.json` 的 `ownershipV2`。该策略让任务完成入口保留 Git 载体并关闭正式交付登记，由原定时器按归属收尾。V1 名单仍可由原授权入口独立处理。

V2 读取当前关闭登记及可核实的历史关闭登记。准确交付的 main 和候选必须可从当前远程 main 追溯。正式回执、阶段记录、冻结及必要交付摘要留在原位置。会根据任务登记识别 Git Worktree、任务交付目录、保全目录及已登记的外部源码副本。嵌套源码副本要求独立对象库、同源 Git 仓库、干净工作区和可追溯提交。未能证明归属或独立用途的内容会记录待处理原因。

每轮最多 10 个处理单元、120 秒、1 GiB 逻辑字节。目录文件逐项验证身份，持久保存删除进度，下一轮重验引用后接续。单文件超过可用预算时保留并记录原因。待清理对象出现新内容、链接、共享副本、媒体、备份、配置或不明引用时保留。Git 工作区干净且确认没有残留后使用 Git 移除，符合条件的同名远端分支使用精确旧值保护删除。新的或已复用的分支保留。

只有准确标识为任务测试夹具的本地 MySQL 容器和卷进入自动回收，SQL 先核查外部连接、库名和残留，Docker 再核查卷引用与实际移除。任务预览、业务媒体、共享卷和必要备份继续受保护。

每个任务的本机处理状态保存在 `.git/task-cleanup/ownership-v2/<task>.json`。进度记录包含待处理原因和首次异常。任务关闭、当轮清理结果和最终零残留分别核验。没有测到物理释放量时记录未知。
