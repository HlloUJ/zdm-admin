# 独立任务并行计时

## 目标与保留约定

沿用现有计时器，记录每个独立任务和每次执行过程，以便优化效率。不修改调度、验证要求、审批、交付或清理权限，不安装监控，不重跑历史任务。

原生整轮计时保持原契约：只有验证过的授权消息和最终轮次结束，才能给出从用户指令到完成的完整耗时。无法读取原生来源时，不把登记、绑定或首个命令当作用户授权时间。旧时间线、摘要和正式回执不修改；旧 `--batch` 查询和校验不变。

## 记录入口

- 已发布 `task:entry` 在实际执行时按独立任务记录命令开始/结束和结果；只读查询、计划不记成执行。工作区准备、依赖安装、开发checkpoint、预览、数据准备、交付、组合分别标记。入口记录失败只告警，不能改变业务命令结果。
- `task:start` 保存原生计时绑定结果及失败原因，不再仅在启动输出里出现。依赖准备独立记录，和启动外层有重叠，不能相加。
- 既有验证执行器在写入原始attempt时，同时保存本次验证起止到Git公共目录；工作区清理不丢失这些时间证据。重复观测幂等，冲突拒绝覆盖。原始验证报告仍是质量证据，计时不是。
- 未经过生命周期入口的开发、定向测试或明确资源等待，由执行代理使用 `npm run task:timing -- --measure development -- <原已授权命令> [参数]`；可选阶段为 development、validation、resource-wait、approval-wait、merge、cleanup、dependencies。该包装只度量这个命令，不授权命令，也不把整段聊天都说成开发。参数与输出不写入计时。不要将无等待原因的空档标成资源等待。
- 合并、CI、交接、清理继续读取原正式交付分阶段回执，不改变原流程；有开始无结束、恢复时才补出的结束上界，不计入确定执行时长。

## 并行报告

`npm run task:timing -- --parallel --json` 只读取登记任务、持久化过程事件、既有验证attempt、正式交付回执和校验后的原生摘要，不读取会话正文、不启动采集器或测试、不改任务状态。

逐任务保留登记、依赖完成、正式交付开始、关闭里程碑。收到需求、开发、用户验收、资源等待、合并或清理没有证据时保持未知，不能根据状态或相邻时间补造。

- wholeTaskWallMs：仅完整原生摘要提供；否则null。
- observedWindow：最早过程记录或登记至当前/关闭，仅观察窗口，不是用户等待总时长。
- observedProcessWallMs：有完整起止过程的时间并集，包含过程内部等待，不是CPU使用时长。
- parallelOverlapMs：至少两个不同任务有已闭合过程重叠的墙钟时间；同任务嵌套不增加并行数。
- sumTaskProcessMs：各任务过程时长之和，只作累计量展示，不冒充全局墙钟。
- coverageRatio/unknownMs：观察窗口内有闭合过程证据的覆盖率和未知区间。覆盖率不是测试覆盖率，也不是效率得分。没有原生边界时不声称覆盖了收到指令以前的时间。
- waitingWallMs：明确CI/资源/审批等待区间并集，是覆盖指标，不加到过程墙钟上。

尚未结束的过程、损坏记录、时钟倒退/未来时间、冲突记录保留pending/issues。进程消失不能自动补结束；实际资源恢复仍交由284及原工具核验。本功能不停止进程、释放锁或自动重试。

## 数据位置与边界

原 `task-timing/<task>/` 保持不动。新增过程事件在Git公共目录 `task-timing-events/<task>/`，每事件独立不可覆盖文件，多个任务无需争用全局计时锁。保存仅任务身份、阶段、事件时间/结果和绑定诊断，不保存聊天、代码、命令参数或输出。未接入包装的任意文件编辑、模型思考和其他工具调用无法凭空计时；报告明确未知，不以0替代。

## 自动采集覆盖核对（当前候选，不代表已启用）

| 环节           | 实际自动来源                                                   | 尚缺边界                                                           |
| -------------- | -------------------------------------------------------------- | ------------------------------------------------------------------ |
| 收到用户需求   | 仅原可信原生摘要                                               | 宿主未暴露逐调用无正文元数据接口；缺摘要时未知                     |
| 工作区、依赖   | task:entry start 外层与 task:start 依赖事件                    | 绕过正式入口的准备不自动记录                                       |
| 开发           | checkpoint 命令本身                                            | 分析、编辑、直接工具调用未自动采集；不能以 checkpoint 耗时代表开发 |
| 检查、测试     | verification-runner 的 attempt                                 | 任意直接测试命令不自动采集                                         |
| 资源等待       | scheduler 已有状态事件具备 at/task/job/from/to，可后续只读接入 | 当前未接入；初始 queued 没有登记时间，不可倒推                     |
| 用户验收       | accepted-source 是冻结身份凭据                                 | 无验收时间；不得用 mtime 或 Git 提交时间冒充用户验收               |
| CI、合并、清理 | 正式交付分阶段闭合回执                                         | 任意外部动作、无结束事件不精确计时                                 |
| 关闭           | registry.closedAt、正式交付 closedAt（各自语义）               | 不等同原始指令至关闭的全程耗时                                     |

现有宿主线程工具提供状态、轮次摘要或完成通知，不提供逐工具调用 start/end 的纯元数据流。`measure` 是已有授权命令的可选度量包装，不是已实现全部自动覆盖的证明；不为计时更改业务执行机制或读取私有会话。

独立审查发现并修正：仅持久化 start 时补读经工作区身份验证的原 completed；跨工作区或无身份原报告不归属当前任务；时间冲突保留未知。重复观测不重复计时；中断未闭合不推算持续执行。
