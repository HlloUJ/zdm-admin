# 任务中断监测（284）

## 当前产品边界

284 只负责新任务监测登记、只读检查，以及确认中断后在原 ChatGPT 对话通知用户。不自动续接、不接管 owner、不重放命令、不创建或重试 PR/CI，也不解除任何暂停。

旧的 284 自动续接、开发等待交接、恢复准入、CI 续接适配器、owner 交接评估和“成功续接”通知代码已移除。正式交付原恢复入口及共享进程监督器保留；921 的资源调度已由独立退役变更移除。

## 只读观察入口

`node scripts/task-continuity-cli.mjs --once [--task <准确任务ID>]` 读取既有登记、正式阶段记录及旧验证摘要，写观察器私有快照。`--watch` 每分钟重新读取，进程退出即停止，不代表已安装常驻服务。

CLI 不发送通知、不更新任务总览、不输出执行 handoff。已删除旧 `--admission` 和 `--notify` 开关。快照始终标记 `automaticResumptionEnabled:false`。

观察器保留四个导出：

- `probeOwner`：只做进程存在性观察；PID 存在不证明原执行身份。
- `inspectTaskContinuity`：区分已记录执行者消失、已记录失败、显式暂停、身份不明和缺失记录。
- `verificationObservations`：旧 running 汇总只能标为待核实，不能据此断言中断。
- `collectTaskContinuity`：读取登记中的未关闭任务，不修改原阶段、锁、队列或执行结果。

## 通知与判定

新任务先建立准确 task、原 owner、worker、原对话及授权来源的监测登记。确认中断的 ChatGPT 通知由独立通知模块和根线程消息工具处理；发送前核对最新证据及暂停状态，未知发送结果先读回，不盲目重发。

无 instrumentation、未知 worker、PID 复用或探测权限不足，不等于任务中断。电脑离线、监测读取失败和损坏记录属于监测问题，不能伪报业务失败。已完成任务和用户暂停优先排除。

观察成功不等于通知已投递；消息投递不等于业务恢复。实际持续监测与消息可达性需要单独核验，候选代码及隔离测试不能代替上线证据。

## 历史现场

删除源码不删除 `.git` 中历史 enrollment、claim、attempt、receipt、暂停、未知结果及正式交付记录。它们保留供审计，不构成新的执行授权。不得为清理本功能擅自解除锁、杀进程或改动预览及业务数据。
