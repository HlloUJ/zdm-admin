# 门店款项配置后端补齐 PRD

版本：V1.0 草案

日期：2026-11-06

状态：D1至D4规则已确认；用户已于2026-11-06授权实施，款项配置代码、专项验证及5175真实联调已完成。

## 1. 目标与范围

将门店端“订单管理 → 款项配置”从浏览器本地原型改为服务端持久化，使同一门店有相应权限的人员在不同设备上使用同一份配置，并由后端强制校验身份、权限和门店归属。

本次只补齐款项名称配置及其前端接入。保持当前菜单、页面样式、字段、确认弹窗、成功提示和操作入口。销售订单、收退款单据、库存、履约、供应链、在线支付及退款通道不在本次后端实施范围。

## 2. 现状与依据

当前页面已有新增、编辑、启用、停用、删除，展示名称、状态、创建人、创建时间；按创建时间倒序。新增项默认启用，名称去除首尾空格后不能为空，同一门店内款项名称不允许重复。

清理后的活动配置位于订单原型状态的 paymentNames 数组，随整份状态保存在 localStorage，未接业务后端。配置只剩“款项名称”，不再提供收款或退款渠道配置。原型收退款记录以 nature 字符串保存登记时名称，配置变更不回写它。

依据：本次会话已确认规则；src/pages/order/prototype/index.vue、model.ts、resources.ts；docs/product/store-order-prototype.md。早期“款项性质”“收退款配置”等名称已被后续确认替代，不恢复。

## 3. 使用者与数据归属

- 数据属于当前门店，由门店统一维护，不属于某一导购个人，也不是平台公共字典。
- 创建人仅用于记录来源，不决定其他同店人员是否能查看或维护。
- 同店操作能力沿用统一终端功能、角色权限及适用数据权限结果；不在模块中另设“管理员、店长专属”白名单。
- 同租户不同门店也不能互相读取和修改配置。当前身份不能通过提交其他门店ID来切换作用域。
- 运营平台、供应商、供应链、消费者端不新增管理入口；“all”权限不能替代合法门店身份与组织范围校验。

## 5. 状态与选择规则

正常管理状态为“启用”“停用”；删除后从管理列表移除。

启用可以停用；停用可以启用；两种状态都允许编辑和删除。编辑不自动启用，删除不自动恢复。

收款选择器仅展示当前门店启用且未删除的款项名称，没有可用项时明确提示尚无可用款项名称，不自动创建，不允许导购绕过配置自由输入。没有配置管理权限的人员，不应仅因此失去其已获授权的收款选择能力。

前端已打开收款表单后，如果配置被其他人改名、停用或删除，不应静默替换其已选内容。真实收款接口上线后，提交时由服务端重新校验并提示刷新；本次原型接入只能处理前端提示，不能声称具备真实收款事务校验。

## 6. 历史保护

1. 配置ID是关联标识，名称是可变展示值；不能只用名称识别某条配置。
2. 登记收款时，记录配置ID及当时名称快照。查询历史时使用快照，不实时联查配置名称来替换历史。
3. 例如登记“定金”1000元后，将配置改名为“预付款”，历史仍显示“定金”；未来新登记才显示“预付款”。
4. 停用、启用、删除不调整历史金额、收款性质、订单状态或成交金额。
5. 原型现有 nature 文本保留。旧记录缺少配置ID时不得按名称或排序猜测关联，也不得以当前配置名称覆盖它。
6. 本次不迁移销售订单和收退款的持久化；未来真实收款后端须在事务中补齐配置校验与快照写入，才能完成服务端历史保护闭环。

沿用现有资源，不改名、不默认授予旧角色：

现有5175前端原型的临时可见授权不自动进入后端、生产环境或真实角色分配。

## 8. 异常与刷新

- 名称为空或重复：定位名称字段并保留输入。
- 网络失败：显示失败及可重试入口，不显示空列表冒充无数据，不回退本地旧配置。
- 权限失效：拒绝后续请求，清除本页旧作用域数据，按统一权限流程处理。
- 切换门店或身份：清空上个身份的列表、选中项和编辑状态，再加载当前作用域；旧请求迟到不得覆盖新作用域。
- 记录被其他人删除：提示记录已变化，刷新列表，不重新创建。
- 删除当前页最后一条：回到仍合法的页码，避免停留在超出范围的空页。
- 多人并发修改：采用内部版本校验，版本过期时拒绝覆盖并提示刷新；不提供版本管理页面、历史版本切换或恢复功能。

## 10. 验收标准

| 场景                 | 预期                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------ |
| 新门店第一次打开     | 空列表，无默认款项。                                                                 |
| 名称长度             | 新增、编辑时10个字符允许保存，超过10个字符拒绝并定位名称字段；直接调用接口同样受限。 |

| 伪造创建信息和门店   | 服务端拒绝或忽略伪造字段，绝不改变安全归属。                                         |
| 已删除项             | 不再出现在管理列表及可选项；重复删除不影响其他记录。                                 |
| 切换身份时旧请求迟到 | 不泄露、展示或覆盖其他门店配置。                                                     |
| 请求失败             | 不显示成功、不丢输入、不使用localStorage降级。                                       |
| 原型订单回归         | 客户、金额、优惠、收退款、发货、分页和列表视觉不因配置接入而变化。                   |

## 11. 实施完成定义

配置数据库、后端接口、前端接入、权限强制点和组织隔离均完成，适用验证通过，真实预览接口写入可在数据库复核，才可称为“款项配置后端已补齐”。

这不代表销售订单、收退款、支付通道或整个订单管理后端已经完成。正式提交、集成、合并和运行交接另按项目交付流程执行。
