# 门店订单前端原型

本阶段确认门店订单的页面、交互和官方视觉，不实现业务后端、数据库迁移、支付、真实库存或供应链接口。依据为本轮确认的订单需求。

## 页面与数据边界

订单管理仅门店端可见，含销售订单、履约任务、款项配置。列表使用 AdminListPage，表单使用 AdminFormDialog，详情使用 AdminDetailPage。五个状态为待确认、已确认、已发货、已完成、已取消；默认待确认，按进入当前状态时间倒序。

浏览器模拟数据按租户、门店、身份和账号隔离，不导入真实客户，不请求业务写入接口。前端接入权限资源不代表服务端权限闭环，已有角色不会自动授予新权限；有 all 的门店开发身份可预览，其他身份按实际授权显示。前端专用模块策略只允许 store，不修改后端策略或真实角色授权。

## 产品边界

- 待确认可编辑、登记线下收退款，不占库存、不发货；确认后锁定交易内容。
- 同 SKU 一条明细；确认前可换 SKU，不能只改商品文字代表另一种实物。
- 成品现货缺货不能确认；标准配件可缺货等待补货。供应链统一维护库存，上架不等于实物在本店。
- 商品折扣与整单折扣互斥，之后允许减免和抹零；运费是否参与整单折扣可选。
- 确认后可调整运费、交期及负责人；取消未发商品可重新结算剩余优惠，保留原确认金额及前后记录。
- 收款不限制确认和发货；全发且净收款达到有效成交金额自动完成。完成后更正导致差额只标警告，不回退状态。
- 供货路径为本店实物直交、供应链直发客户、供应链中转门店。中转到店不计入客户已发数量。
- 不做历史补录、母子或关联订单、跨订单统一收款发货、固定收款计划。
- 客户永久编号关联历史；当前独立建档，不做全局去重合并，同号另建填写原因。订单快照不反向修改客户档案。
- 成交时间是首次确认时间。整单取消保留原交易，应收归零，禁止新增收款。

## 原型覆盖和后续接入

本地模拟开单、复制、库存确认、价格计算、收退款新增更正作废、安排、到店收货、客户发货、更正发货、取消结算、交期负责人调整、配置停用和日志。凭证在本机读取，不上传服务器。

供应链货源、采购及直发反馈后续接入；模拟通知只是本地日志，不是真实送达。模拟库存不承担真实跨用户并发安全。后端接入需实现统一有效权限、组织隔离、库存事务和真实凭证生命周期。

销售订单属于门店私有；供应履约属于跨组织协作，由后端阶段落实参与方视图。履约任务界面不因可执行任务就获得销售金额查看权限。

批次 store-order-prototype，模块 order-prototype。菜单、路由与候选资源统一使用 store.order-management 编码。资源注明前端原型，不宣称已具备后端授权能力。

## 本机预览例外

用户批准仅在开发模式、本机 HTTP 5175 端口，为门店身份开放订单原型菜单及模拟操作。不写入账号权限，不更改角色授权，不开放其他模块；其他端口、生产构建及非门店身份仍按真实权限控制。

款项配置仅维护款项名称，不预置数据，支持新增、编辑、启停和删除，保存创建人及时间。历史收退款保留登记时的名称快照，配置变化不回写历史订单。

渠道不提供自由配置。当前线下登记提供现金、银行转账、微信、支付宝固定记录选项；后续在线支付由实际接入及开通的渠道决定。原有收退款渠道快照保留，停止消费旧渠道配置。

## 订单编号

订单号由系统自动生成且不可编辑：`XS + Unix 秒时间戳 + 三位随机数字`，时间戳取当前毫秒时间戳除以1000后向下取整，随机数不足三位补零。重复则重新生成，并与全部历史订单校验。当前原型检查本地模拟订单，创建和复制时生成、保存前再次排重；正式后端须全局唯一约束配合碰撞重试，跨门店、跨年及并发下均不可重复。已有订单号保持不变。

## 2026-10-21 指定视觉：分区摘要卡片

唯一参照为用户明确指定的 `exec-36b11d81-a9a5-4237-89d4-0168e81f9332.png`（图内标注“方案四·分区摘要卡片”）。此前“双行订单摘要”实现不再作为视觉依据；不再以展示顺序或方案编号推断所选图片。

仅调整右侧销售订单页，顶部导航和左侧菜单保持原实现。复用 `AdminListPage` 的数据与分页入口，专用 `SalesOrderList.vue` 提供原图中的状态 Tab、单行查询、独立新增按钮、订单卡片标题和操作、客户与业务分区、可收起的商品明细。默认待确认；首次进入列表展开首张卡片，其他卡片收起，可分别展开多个。切换状态和查询仍按既有规则清空展开状态。只有数据超过当前页容量时显示原分页入口。

订单号、客户、负责人、创建人、创建时间、成交金额、收款、发货和异常均保留；详情与订单号点击均可进入详情，原编辑、确认、复制、收退款等操作按原权限进入“更多”。原价格明细和调整记录仍可在详情查看，不额外添加原图没有的卡片底部结算栏。图中“已发2/共6”与明细1+4矛盾，实际页面始终依据有效商品件数计算总量。

商品明细合并图片和名称为“商品信息”，其余列为SKU编码、规格、单价（¥）、购买数量、金额（¥）、发货进度。金额仍按计价数量和折扣计算，发货按实际件数计算，不改业务模型。无图种子餐桌、餐椅使用原图照片区域作静态缩略图；真实订单图片优先，其余无图显示占位。原图仅用于这两个商品照片，不替代页面的任何控件、文字或交互。

本页专用布局、颜色和占位例外登记在 `docs/ui/visual-refactor.json`。短占位只允许该文件中带精确标记的选择器和日期控件；浅色详情按钮边框只允许精确文件、选择器、属性和值，不允许其他页面、主题或禁用态继承。保留全局默认规范及全部原负向守卫，并增加针对例外越界的测试。

浏览器验收使用独立测试会话和隔离模拟数据，检查与原图等宽的右侧区域及1368px窗口；不读取或改动用户当前标签页的本地订单。后端、支付、真实角色和实际库存未改变。

### 列表后续反馈

状态Tab展示当前权限及门店数据范围内各状态的订单总数（含0，不随列表查询条件改变）。日期查询名称为“创建时间”，按订单创建日期筛选，包含未确认订单；订单成交时间本身及统计口径不变。卡片“更多”更名“操作”，下拉菜单使用TDesign公开列宽属性完整展示操作名称，权限及操作行为不变。

状态Tab与查询条件共同置于一个白色区块，使用统一外边框及圆角；新增操作栏和订单卡片仍独立于该区块。

整页视觉复核继续以指定原图为依据，组件默认值不作为验收结论。原图Tab中文字实际墨迹高度约13px，页面用14px正文、选中项14px强调字重对应；金额按原图提升为18px。订单号内距、摘要分区列位、商品表列位、首项/其他商品名称字重、状态底色、异常底色、商品区域底色及发货按钮宽度均按图复核。保留用户已确认的全局页面背景、Tab与查询共用白色块、状态计数、创建时间查询、操作菜单和完整名称展示。
